# 感性学習（kansei）

## なぜこのスキルがあるか

AI に「このサイトを参考に作って」と頼むと、色やフォントの名前は拾えても、出来上がりは「どこかで見たような無難なもの」になりがちです。原因はおおむね次の3つです。

1. **表面の名詞だけを拾う** —「白基調・青・ゴシック体」までは分かるが、その良さを生んでいる余白の量、文字サイズの比、色の面積比、間の取り方といった**量と関係**を拾っていない。
2. **平均に寄せる** — 迷うと「よくある良いデザイン」に戻る。参考作品の良さは、たいてい平均からの**意図的なずれ**（極端な余白、1色だけの強いアクセント、あえての不揃い）にある。
3. **足し算をする** — 良くしようとして装飾・影・グラデーション・動きを足す。良い作品の多くは**何をしていないか**で品位が決まっている。
4. **決めていない所を既定値で埋める** — プロファイルに書いていない部分（ボタンの形、見出しの言い回し、カットの長さ）を AI のいつもの選択で埋める。一つひとつは無難でも、それが積み重なると一目で「AI が作った」と分かるものになる。

このスキルは、作品を要素に分解し、各要素について「何が（観察）」「なぜ人は良いと感じるか（効果）」「どうすれば再現できるか（数値・ルール）」を書き出し、さらに制作物のすべての判断を参考作品かユーザーの言葉まで辿れるようにすることで、この4つを防ぎます。AI っぽく見える典型と、その消し方は `references/ai-tells.md` にあります。最終的な判断基準は**人間（ユーザー）の感性**です。AI の分析は仮説であり、ユーザーの「ここが好き」「これは違う」で修正していきます。

## 3つのモード

依頼に応じてモードを選びます。続けて使うことが多いです（学習 → 制作 → 講評）。

| モード | いつ | 出力 |
|---|---|---|
| **学習** | 参考作品を渡されたとき | 感性プロファイル（Markdown ファイル） |
| **制作** | プロファイルを使って何かを作るとき | 制作物＋どの要素をどう反映したかの対応表 |
| **講評** | 作ったもの（AI製・人製どちらも）が「イマイチ」なとき | 要素別のズレと、具体的な修正案 |

## モード1：学習

### 手順

**1. 作品を手に入れて、実際に見る（聞く）**

推測で語らず、まず実物から事実を集めます。分野別の観察方法と、数値の取り方は参照ファイルにあります。該当するものを読んでください。

- Webページ・アプリ画面・スライド → `references/web.md`
- 動画・映像・アニメーション → `references/video.md`
- 美術作品・イラスト・写真・ロゴ・グラフィック → `references/visual-art.md`
- 音楽・音声・効果音 → `references/music.md`
- 文章・コピー・ネーミング・その他（料理、空間、プロダクトなど） → `references/other.md`

AI が直接知覚できないもの（音、動画の動き、触感、味など）は、ツールで取り出せる情報（波形の解析、フレームの切り出し、楽譜・歌詞、メタデータ）で補い、それでも足りない部分は**ユーザーに印象を聞く**か、プロファイルに「未確認」と明記します。分かったふりをして書くのが一番まずい結果になります。

**2. 第一印象を言葉にする（全体）**

分解する前に、全体として何を感じさせる作品かを決めます。分解の後だと細部に引っ張られて見失うからです。

- 一言でいうと：例「静かな自信」「手触りのある温かさ」「緊張感のある高級感」
- 誰に向けて、どんな気持ちにさせたいか（想定される受け手と目的）
- 印象を表す形容詞を対で：例「明るい⇔暗い」「親しみ⇔格式」「静⇔動」「緻密⇔おおらか」のどこにあるか。5段階などで位置を示す

「モダン」「洗練」「シンプル」「おしゃれ」のような**どの作品にも当てはまる言葉だけで終わらせない**でください。使うなら「何によって」そう感じるのかを必ず添えます（例：「シンプル＝1画面に要素が3つ以下、色は無彩色＋1色」）。

**3. 要素に分解して、要素ごとに3段で書く**

分野ごとの要素一覧は参照ファイルにあります。各要素について次の3段で書きます。

| 段 | 内容 | 悪い例 → 良い例 |
|---|---|---|
| 観察（事実） | 測れる・指させる事実。数値、比率、具体名 | 「余白が広い」→「セクション間 160px、本文幅 640px で画面の 45%」 |
| 効果（なぜ良いか） | 人の知覚・心理にどう働くか | 「おしゃれ」→「要素が少なく視線が迷わないため、見出しが一度で目に入り、落ち着いた印象になる」 |
| 再現ルール | 別の制作物で守るべき具体的な決まり | 「余白を広めに」→「セクション間は本文行間の 6倍以上。迷ったら増やす方向」 |

効果を説明するときに使える知覚・心理の原則は `references/principles.md` にまとめてあります。原則名を書くこと自体が目的ではありません。「なぜ人がそう感じるか」を自分の言葉で説明できることが目的です。

**4. 要素どうしの関係を見る**

良さは単独の要素より、組み合わせに宿ることが多いです。特に次を確認します。

- **主役と脇役**：何が一番目立つように設計されているか。他の要素はそれを邪魔しないためにどう抑えられているか
- **対比とそろえ**：どこで大きな差（サイズ・色・速度・音量）をつけ、どこを揃えているか
- **リズム**：繰り返しと変化の周期（スクロールしたとき、時間が進んだとき）
- **一貫性**：全要素が同じ「性格」で揃っているか（例：丸い書体＋角丸＋柔らかい言葉づかい）
- **やっていないこと**：普通ならやりそうなのに、あえてやっていないこと。これは見落としやすいので、必ず3つ以上探す

**5. 平均との差（その作品らしさ）を特定する**

「同じジャンルのよくある作品」を思い浮かべ、それと比べて何が違うかを書きます。ここが**AI が平均に戻らないための最重要項目**です。「ここを普通にすると、この作品らしさが消える」という点を優先度順に並べます。

あわせて、**AI が同じお題で作ったらどうなるか**も書きます（`references/ai-tells.md` の該当分野を見る）。参考作品がその典型をどう避けているか、逆に典型と同じ要素を使っていてもなぜ AI っぽく見えないのか（どの具体性・どの例外が効いているか）を書くと、制作時に「避けるべき既定値」として使えます。

**6. ユーザーに確認する**

分析を見せて、短く聞きます。質問は多くても3つまで。

- 「この中で特に好きなのはどこですか？逆に、真似しなくていい部分は？」
- 「一言でいうと〇〇な印象と読みましたが、合っていますか？」

ユーザーの答えはプロファイルの「ユーザーの言葉」欄にそのまま残し、分析より優先します。ユーザーが急いでいて確認を省きたい場合は、仮のプロファイルとして保存し、その旨を書いておきます。

**7. 感性プロファイルとして保存する**

`assets/profile-template.md` の形式で書き、作業フォルダの `kansei/` フォルダに `<作品名や短い名前>.md` として保存します（フォルダがなければ作る）。ユーザーが別の場所を指定したらそれに従います。参考画像（スクリーンショットなど）を撮った場合は同じフォルダの `kansei/img/` に置き、プロファイルから参照します。

複数の作品を学習した場合は、共通点を「好みの傾向」としてまとめた `kansei/_好みの傾向.md` を作るか更新します。何作品にも共通して出てくる特徴こそ、ユーザー固有の感性である可能性が高いからです。

## モード2：制作

1. 使うプロファイルを読む（`kansei/` にあるもの。どれを使うか不明ならユーザーに聞く）
2. 作り始める前に、プロファイルの「再現ルール」と「平均との差」から、今回の制作物で守る項目を**具体値つきで**書き出す（例：本文 17px／行間 1.9／アクセント色 #D9480F は面積 5% 以下）
3. **既定値を先に宣言する**：プロファイルを見ずに作ったら自分がどうするか（配色・書体・構成・言い回し・動き・尺など、分野の主要な軸ごとに）を短く書き出す。これが今回避けるべき「AI っぽい答え」の具体像になる。書き出した既定値と同じものを使うのは、プロファイルに根拠がある場合だけ
4. 制作する。内容（テキスト・用途）が参考作品と違うのは当然なので、**値をそのまま写すのではなく、ルールと比率を写す**。参考作品の文言・画像・ロゴなどの固有の創作物はコピーしない。プロファイルに書いていない部分は既定値で埋めず、参考作品の性格（「4. 要素どうしの関係」の一貫した性格）から決めるか、この案件の内容・受け手から理由をつけて決める
5. **根拠トレース**：完成したら主要な判断（色・サイズ比・余白・書体・構成・言い回し・動き等）を一つずつ挙げ、「プロファイルの何番」「ユーザーの言葉」「この案件の内容」のどれから来たかを書く。どこにも辿れない判断は既定値の漏れなので作り直す
6. モード3の講評（AI っぽさの点検を含む）を自分で一度かけ、ズレを直してから渡す
7. 渡すときに「どの要素をどう反映したか」の短い対応表を添える。ユーザーがどこを直せばいいか判断しやすくなるため

## モード3：講評

1. 対象を実際に見る（Webならブラウザで表示してスクリーンショット、数値も取る）
2. プロファイルの要素ごとに、参考と対象を並べて比較表を作る：「要素｜参考｜対象｜ズレ｜修正案」
3. ズレを**印象への影響が大きい順**に並べる。たいてい上位は余白・サイズ比・色の面積比・情報量（足しすぎ）で、細部の色味やフォント名は下位になる
4. 修正案は「もっと洗練させる」ではなく「見出しを 32px→48px、本文との比を 1.6→2.8 にする」のように実行できる形で書く
5. **AI っぽさの点検**：`references/ai-tells.md` の該当分野の典型（第1層・第2層）に当てはまる箇所を数え、プロファイルに根拠のないものを修正対象に加える。あわせて次の2つを確認する
   - **入れ替えテスト**：固有名詞・ロゴ・商品名を別の案件のものに差し替えても違和感がないなら、その案件専用の判断がまだ足りない
   - **既定値との比較**：モード2の手順3で書いた既定値と並べ、主要な軸の半分以上が同じなら作り直す
6. プロファイルがない場合は、まずユーザーに参考作品があるか聞く。なければ、ユーザーの不満の言葉（「なんか安っぽい」「AI っぽい」等）を手がかりに、`references/principles.md` と `references/ai-tells.md` の観点で原因の候補を挙げる

講評の結果ユーザーが新しく「これは違う」「ここが好き」と言った内容は、プロファイルに追記して育てていきます。

## AI が陥りやすい罠（自己チェック）

学習・制作・講評のどの段階でも、仕上げる前にこれを見直してください。

- [ ] 「モダン」「洗練」「シンプル」「スタイリッシュ」などの言葉を、根拠（数値・具体物）なしに使っていないか
- [ ] 色名・フォント名を書いただけで、**面積比・サイズ比・余白量**を書き漏らしていないか
- [ ] 「やっていないこと」を探したか
- [ ] 制作で、参考にない影・グラデーション・角丸・アイコン・動きを足していないか
- [ ] 迷った箇所を「よくある無難な値」で埋めていないか（参考作品の極端さを中和していないか）
- [ ] 制作物の主要な判断を、すべてプロファイル・ユーザーの言葉・案件の内容のどれかまで辿れるか
- [ ] `references/ai-tells.md` の典型（特に第2層の「上品な定型」）を、根拠なく使っていないか
- [ ] AI っぽさを消すために、理由のないランダムな崩しやノイズを足していないか
- [ ] プロファイルや講評の文章そのものが、`references/ai-tells.md` の「文章・コピー」の典型（対比構文、三点列挙、抽象語）で書かれていないか
- [ ] 知覚できなかった部分（音・動き等）を推測で断定していないか
- [ ] ユーザーが言った「好き／違う」を、自分の分析より優先しているか
