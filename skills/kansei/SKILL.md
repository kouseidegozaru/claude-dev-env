# 感性学習（kansei）

## なぜこのスキルがあるか

AI に「この作品を参考に作って」と頼むと、出来上がりは「どこかで見たような無難なもの」になりがちです。原因は次の4つです。

1. **表面の名詞だけを拾う** — 色名・書体名は拾うが、良さを生んでいる余白の量・サイズの比・色の面積比・揃え方（**量と構造**）を拾わない。
2. **平均に寄せる** — 迷うと「よくある良いデザイン」に戻る。参考の良さは平均からの意図的なずれにある。
3. **足し算をする** — 装飾・影・グラデーション・動きを足す。良い作品は「何をしていないか」で品位が決まる。
4. **決めていない所を既定値で埋める** — 作る前に決めたつもりでも、作る途中でいつもの選択に戻る。積み重なると一目で「AI が作った」と分かる。

このスキルは、分野ごとの「必須の軸」で参考を測り、作る前に**決定表**で値を固定し、作った後に**同じ測り方で実物を照合**して、この4つを手順として潰します。AI の分析は仮説で、**最終判断はユーザーの感性**です。

## 全モードで守ること

- 参考作品の文言・画像・ロゴなど**固有の創作物はコピーしない**。写すのはルールと比率。
- 軸は分野別ファイル冒頭の「**必須の軸**」1か所だけを使う。学習で取る値、プロファイルの再現トークン、決定表の行は同じ一覧。
- 見ていない・聴けないものを断定しない。取れない値は「未確認」。**数値と目視が食い違ったら目視を採り**、食い違いをプロファイルの「未確認・推定」に書く。
- 書き方は「観察（測れる事実）→ 効果（なぜ人が良いと感じるか）→ 再現ルール」。例:「余白が広い」→「セクション間 160px＝本文行送りの 6 倍」。
- ユーザーの言葉は原文のままプロファイルの「ユーザーの言葉」に足し、自分の分析より優先する。

## 分野別ファイル（必須の軸・測り方・見落としやすい点）

| 対象 | 読むファイル | 測る道具（`scripts/`） |
|---|---|---|
| Webページ・アプリ画面・スライド | `references/web.md` | `measure-web.mjs`（無ければ `measure-page.js`＋`count-colors.py`） |
| 動画・映像・アニメーション | `references/video.md` | ffmpeg（コマンドは video.md）、`measure-audio.py` |
| 写真・イラスト・美術・ロゴ | `references/visual-art.md` | `count-colors.py` |
| 音楽・音声・効果音 | `references/music.md` | `measure-audio.py` |
| 文章・コピー・ネーミング・その他 | `references/other.md` | `measure-text.py` |

道具の動かし方（`S` はこのスキルの `scripts/` の絶対パス。保存先は作業フォルダの `kansei/img/`）:

```
NODE_PATH="$(npm root -g)" timeout 120 node $S/measure-web.mjs --selftest        # Web を測る前に1回。FAIL なら目視を主にする
NODE_PATH="$(npm root -g)" timeout 120 node $S/measure-web.mjs <HTML|URL> --out kansei/img --name <名前>
NODE_PATH="$(npm root -g)" timeout 120 node $S/measure-web.mjs --pair <参考> <制作物> --out kansei/img
timeout 120 python3 $S/measure-text.py <文章.md>      # 文章
timeout 300 python3 $S/measure-audio.py <音声> --spectrum kansei/img/spec.png   # 音・動画の音
timeout 120 python3 $S/count-colors.py <画像>         # 画像の色の面積比
```

Playwright が見つからないと言われたら `references/web.md` の「Playwright が無いとき」に従う。

## 3つのモード

| モード | いつ | 出力 |
|---|---|---|
| **学習** | 参考作品を渡されたとき | 感性プロファイル（`kansei/<短い名前>.md`） |
| **制作** | プロファイルを使って何かを作るとき | 制作物＋照合済みの決定表 |
| **講評** | 作ったもの（AI製・人製どちらも）が「イマイチ」「AI っぽい」とき | 並べた1枚、比較表、点検表の結果、修正 |

続けて使うことが多い（学習 → 制作 → 講評）。各手順の「→」の後が、その手順で**必ず書き出すもの**です。書き出していない手順は、やっていないものとして扱います。

## 学習（始める前に `references/learn.md` と該当の分野別ファイルを読む）

1. **実物を見る・測る**: 画像・スクリーンショットは開いて見る。道具で測る。→ 必須の軸の値を全行（取れない値は「未確認」）
2. **ひとこと＋印象の位置**: 分解の前に全体の印象を決める。→ 1文と、形容詞対の5段階
3. **要素ごとに3段**: 観察／効果／再現ルール。→ 要素ごとの3行
4. **関係とやっていないこと**: 主役と脇役、対比とそろえ、リズム、一貫した性格。→ 関係の4行と「やっていないこと」3つ以上
5. **平均との差と AI の既定値**: 普通にすると消える点を優先順に。同じお題を AI が作った姿を `references/ai-tells.md` で書く。参考自身に `references/checklist.md` を掛ける。→ 平均との差のリスト、AI の既定値、**免除リスト**（参考が当てはまった点検項目＝参考の顔）
6. **ユーザー確認→保存**: 質問は最大2問・選択式（下の「往復を減らす」の会話全体の予算の内で）。答えは原文で記録。`assets/profile-template.md` の形式で保存。急ぎなら「仮」で保存。2作品目以降なら `kansei/_好みの傾向.md` も作る・更新する。→ プロファイルのファイル（冒頭に**再現トークン**と免除リスト）、2作品目以降は `_好みの傾向.md`

## 制作（始める前に `references/make-review.md` の「制作」を読む）

1. **プロファイルを読む**（どれを使うか不明なときだけ聞く）。→ 使うプロファイル名
2. **決定表を書く**: 行＝必須の軸（構造の軸を省かない）、列＝「AI の既定値｜今回の値｜根拠｜実物の値」。根拠は (a) プロファイルの節番号＋記述の引用、(b) ユーザーの言葉の引用、(c) 依頼文・資料の該当行の引用 の3つだけ。引用できない根拠は空欄。「今回の値」＝「AI の既定値」で根拠が (c) だけの行が3行以上なら、作る前に (a)(b) で裏づけるか値を変える。→ 実物の値の列が空の決定表
3. **作る**: 値ではなくルールと比率を写す。表に無い判断は、プロファイルの一貫した性格か案件の内容から決め、表に行を足す。→ 制作物
4. **実物照合**: 参考と同じ道具・同じ数え方で制作物を測り「実物の値」を埋める。「今回の値」と違う行は直して測り直す。→ 実物の値が全行埋まった決定表
5. **講評モードを自分にかける**（講評の手順0は飛ばし、手順1から）。→ 講評の出力
6. **渡す**: 照合済みの決定表を対応表として添える。→ 制作物＋決定表

## 講評（始める前に `references/make-review.md` の「講評」と `references/checklist.md` を読む）

0. **入口**: プロファイルも決定表も無い（人の作品・他の AI の作品、「AI っぽいから直して」）なら、参考作品があるか1問だけ聞く。あれば学習の手順1・5を簡易に行う。無ければ、分野の必須の軸ごとに「AI の既定値」をその場で書いて対象と並べ、ユーザーの不満の言葉と `references/ai-tells.md` から原因候補を挙げる（手順2・3はこの表で行う）。→ 参考の有無と、比べる相手の表
1. **実物を見る**: Web は 1440px と 375px（依頼で幅の指定があればその幅も `--widths` で）のスクリーンショットを Read で開いて目視＋スクリプト。画像は開いて見る。動画はフレーム切り出しとカット検出、音は `measure-audio.py`。道具が無ければその旨を書き、ユーザーに印象を聞く。→ 見たファイルと測った値
2. **並べた1枚を作って見る**: 参考と対象のスクリーンショット（または代表フレーム・数値表）を左右に並べる（`measure-web.mjs --pair`）。→ 並べた画像と、見て気づいた差
3. **比較表**: 「要素｜参考｜対象｜ズレ｜修正案」。修正案は「見出し 32px→48px」のように実行できる形。→ 比較表
4. **点検表で採点**: `references/checklist.md` の各項目を Yes/No でなく「参考の○○と同じ／違う」で書く。免除リストの項目は、参考と同じ使い方なら可、参考に無い場所へ広げていれば修正対象。→ 点検表の結果
5. **直す**: 印象への影響が大きい順に直し、手順1〜4をやり直す（最大2周）。残った項目はユーザーに判断を仰ぐ。→ 修正の記録と残った項目

別のエージェントを起こせる環境では、どちらが制作物かを伏せて手順2の1枚を見せる盲検講評を足してもよい（`--pair ... --blind`）。

## 往復を減らす

- **質問は1つの会話で合計3問まで**（学習・制作・講評・分野をまたいで通算）。残りが少ないときは、測っても分からず、ユーザーの言葉でしか決まらない分野（音の「良いところ」、映像の印象など）のために取っておく。
- 依頼文が具体的で、参考を測れば足りるとき（文章の書き方、事実が揃ったお知らせなど）は聞かずに作る。
- 学習の確認は最大2問・選択式。制作前は原則聞かない。決定表に引用で埋まらない根拠の行が残るときだけ1問。
- 講評のあとユーザーが「これは違う」「ここが好き」と言ったら、原文のままプロファイルに追記してから直す。
