# Webページ・アプリ画面・スライド

## 必須の軸

学習で取る値、プロファイルの「0. 再現トークン」、制作の決定表の行は、すべてこの12行です。量の軸（1〜7）と構造の軸（8〜12）の両方を必ず埋めます。参考と AI の既定値が量の軸で重なっていても、構造の軸で差が出ることが多いからです。

| # | 軸 | 何を書くか | `measure-web.mjs` の出力 |
|---|---|---|---|
| 1 | 地色と面積比 | 地の色（html・body を含む）と、画面に占める割合 | `地色（画素）`、`地色` |
| 2 | 文字色・差し色と面積比 | 本文の文字色、差し色（彩度のある色）とその面積、どこに使うか | `文字色・差し色`、`差し色（画素…）` |
| 3 | 書体（実際に描画されたもの） | 指定ではなく描画された書体。太さの種類 | `書体`（描画された実体） |
| 4 | 本文サイズと行間 | 本文の px、行間（倍率）、字間 | `本文サイズと行間` |
| 5 | ジャンプ率 | 最大の文字 ÷ 本文。何が最大か | `ジャンプ率` |
| 6 | セクション間余白 | 大きい切れ目の px と、本文行送りの何倍か | `セクション間余白` |
| 7 | 角丸・影 | 角丸の半径と数、影・グラデーションの有無 | `角丸・影` |
| 8 | 揃え方と左端の揃い | 中央揃えの文字の割合、左端の位置が何本に揃っているか | `揃え方`、`左端の揃い` |
| 9 | ラベルの言語と形 | セクションの目印が英字／和文／番号のどれか、大きさ・字間 | `ラベルの言語と形` |
| 10 | カード・固定ヘッダーの有無 | 箱で囲むか、何枚並ぶか。固定・追従する要素 | `カード`、`固定ヘッダー` |
| 11 | ボタン・リンクの形 | 塗り／線／下線、角の形、数 | `ボタン・リンクの形` |
| 12 | 縦書き・数字の組み方 | 縦書きの有無と場所。数字の大きさ（本文の何倍）、等幅数字 | `縦書き`、`数字の組み方` |

`絵文字・動き` の出力は「C. AI の典型」の点検と、要素一覧の「アニメーション・動き」に使います。

## 観察のしかた

1. **測る道具が動くか確かめる**: `NODE_PATH="$(npm root -g)" timeout 120 node <scripts>/measure-web.mjs --selftest`。同梱の小さな HTML を測り、地色が最大の面積、差し色が少量として出るかを確かめる。FAIL があれば数値より目視を主にし、その旨をプロファイルに書く。
2. **測る**: `measure-web.mjs <HTMLのパス or URL> --out kansei/img --name <名前>`。1440px と 375px のスクリーンショット（ページ全体）と、`<名前>-measure.json` が保存され（依頼で幅を指定されたら `--widths 1440,375,1280,390` のように足す。参考と制作物は同じ幅で測る）、軸ごとの値が `key: 値` で出る。
3. **スクリーンショットを Read で開いて見る**（1440px と 375px の両方）。HTML を読むだけ、数値を見るだけでは見え方は分からない。**数値と目視が食い違ったら目視を採り**、食い違いを「未確認・推定」に書く。
4. **動きを見る**: スクロール、ホバー、読み込み時。必要なら時間をずらして撮るか、`getAnimations()` と transition の値を読む。
5. 画像・スクリーンショットだけ渡された場合: `count-colors.py <画像>` で色の面積比を取り、ほかの軸は画像から読み取って「推定」と書く。

### 数え方の注意（測る道具の限界）

- **色の面積比**はスクリーンショットの画素を数える（各色 6bit に丸め、近い色はまとめる）。要素の面積を足す方法は、重なりや透明な body で狂うので使わない。写真が背景のページでは色が散るので、上位の色を目で確かめて解釈する。
- **書体**は Chromium が実際に描画に使った書体を出す（指定スタックに書いた書体が環境に無ければ、別の書体で描画されている）。制作物と参考は同じ環境で測って比べる。
- **揃え方**は text-align:center と、文字幅ちょうどの箱を margin:auto / flex / grid で中央に寄せたものを数える。段組みの位置の都合で誤判定することがあるので、スクリーンショットで確かめる。
- **ラベル**は「16字以下・本文以下の大きさ・句読点なし」の短い文字列を拾う。ナビゲーションや表の中は除く。拾い漏れ・拾いすぎは目視で直す。
- **固定ヘッダー**は position:fixed/sticky の要素を出す。横長でなければ「ヘッダーではない（追従する縦長・小さい要素）」と出るので、何か（縦書きの店名、目次など）はスクリーンショットで確かめる。
- **gradient 指定**は、小さい `background-size` で繰り返すもの（格子・縞などの模様）を「模様」として分けて数える。それ以外が装飾のグラデーション。
- **セクション間余白**は、文字と画像の縦の切れ目の大きさ。罫線や色面で区切っているページは、スクリーンショットで区切りの位置を確かめる。

### Playwright が無いとき

1. ブラウザで開き、ウィンドウを 1440×900 にしてから、`scripts/measure-page.js` の中身をそのままブラウザの JavaScript 実行ツールに貼って実行する。戻り値の `tokens` が軸ごとの値（色の面積比は含まない）。`viewport` が `0x0` ならブラウザ画面が非表示になっているので、ウィンドウサイズを指定して実行し直す。375px でも同じことをする。
2. ブラウザのスクリーンショット機能で 1440px と 375px のページ全体を保存し、`python3 scripts/count-colors.py <画像>` で色の面積比を出す（Pillow が無くても PNG は読める）。
3. 書体は `measure-page.js` では「指定スタックのうち環境にある最初の書体」までしか分からない。描画された実体はブラウザの開発者ツールの「Rendered Fonts」で確かめるか、「推定」と書く。

## 要素一覧と、見るべき点

必須の軸に加えて、要素ごとの3段（観察・効果・再現ルール）を書くときの一覧です。

| 要素 | 観察すること | 見落としやすい点 |
|---|---|---|
| **フォント（タイポグラフィ）** | 書体（明朝／ゴシック／丸／欧文の種類）、本文と見出しのサイズ、**サイズの比（ジャンプ率）**、太さの数、行間、字間、1行の文字数、欧文と和文の組み合わせ | 字間（letter-spacing）と行間が印象を大きく決める。見出しの字間が広いと上品、詰めると力強い |
| **カラー** | 使っている色の一覧、**面積比**（例 背景 85%：文字 10%：アクセント 5%）、彩度と明度の傾向、純黒・純白を使っているか | 色そのものより面積比と彩度。高級感のあるサイトは彩度が低く、アクセントが極端に少ないことが多い |
| **配置（レイアウト）** | グリッド（列数・揃え）、本文の最大幅、**余白の量**（セクション間・要素間）、視線の流れ（Z型・F型・中央）、左右対称か非対称か | 余白は「空いている」のではなく設計されている。セクション間の余白は本文行送りの何倍か、で記録する |
| **画像・図** | 写真／イラスト／3D／図の別、トーン（色温度・彩度・コントラスト）、切り抜き方、人物の有無と目線、画面に占める割合 | 全画像のトーンが揃っているか。揃っていると世界観が一つになる |
| **トンマナ（全体の性格）** | 第一印象の形容詞、角の丸さ・線の太さ・影の有無など**全要素に共通する性格** | 部品ごとの性格（丸ボタン＋鋭い書体など）が揃っているかどうか |
| **文言（コピー）** | 見出しの長さ、語尾（です・ます／体言止め／呼びかけ）、専門用語の量、数字の使い方、一人称・二人称 | 見出しの**短さ**と、本文との温度差。言葉の量そのものが余白にも影響する。文章の軸は `references/other.md` |
| **アニメーション・動き** | 何が・いつ動くか（読み込み・スクロール・ホバー）、速さ（ms）、イージング、動く距離 | 動きの「少なさ」。良いサイトは動く場所を絞り、速さとイージングを全体で統一している |
| **情報量と密度** | 1画面あたりの要素数、1セクションで伝えるメッセージ数、CTA（ボタン）の数 | AI は情報を詰め込みがち。参考作品の「1画面＝1メッセージ」などの密度を必ず記録する |
| **細部** | ボタン形状、リンクの下線、区切り線、アイコンの線の太さ、フォーカス表示 | 細部の一貫性。ここの不揃いが「安っぽさ」の原因になる |
| **レスポンシブ** | スマホでの文字サイズ・余白の縮み方、並びの変化 | PCの余白比をスマホでどの程度保っているか（375px の測定値と比べる） |

## 制作時の注意

- 参考サイトの値は**比率で写す**：「本文 16px、見出し 56px」→「見出しは本文の 3.5 倍」。
- 決定表の「今回の値」で CSS 変数（デザイントークン）を先に作ってから組み始めると、途中でぶれにくい。
- 外部の Web フォントや CDN が使えない条件では、描画される書体はその環境にある書体になる。書体の軸の「今回の値」は、測って確かめられる形（例: 「ゴシック1書体、太さ 400 のみ」）で書く。
- 完成後は参考と同じ道具・同じ幅で測り（実物照合）、`--pair` で並べた1枚を作って見る（講評）。
