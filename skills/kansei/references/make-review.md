# 制作モードと講評モードの詳細

SKILL.md の制作の手順 1〜6、講評の手順 0〜5 を詳しく書いたものです。

---

# 制作

## 手順1 プロファイルを読む

作業フォルダの `kansei/` にあるプロファイルを読みます。特に冒頭の「0. 再現トークン」「免除リスト」、「2. この作品らしさ」「5. やっていないこと」「6. AI が作るとこうなる」「7. ユーザーの言葉」。どれを使うか分からないときだけユーザーに聞きます。プロファイルが無いときは、先に学習モードを行います（急ぎなら「仮」で）。

## 手順2 決定表を書く

作り始める前に、次の表を**全行**書きます。行は分野別ファイル冒頭の「必須の軸」と同じ（構造の軸を省かない）。表に無い大きな判断（例: ページの構成順、写真の代わりに何を置くか）があれば行を足します。

| 列 | 書くこと |
|---|---|
| 軸 | 必須の軸の名前（分野別ファイルのまま） |
| AI の既定値 | プロファイルを見ずに自分が作ったらどうするか。`references/ai-tells.md` の典型も見て、具体値で書く |
| 今回の値 | この制作物で使う値。比率・数値・「なし」で書く |
| 根拠 | 次の3種類の**引用**だけ。(a) プロファイルの節番号と該当の記述の引用、(b) ユーザーの言葉の引用、(c) 依頼文・資料の該当行の引用。引用できない根拠（「落ち着かせたいので」など自分の説明）は空欄扱い |
| 実物の値 | 作った後に、参考と同じ道具・同じ数え方で測った値（手順4で記入） |

**止まる規則**:

- 「今回の値」が「AI の既定値」と同じ行のうち、根拠が (c) だけの行が **3行以上** あれば、作る前に、その行を (a)(b) で裏づけるか、値を変えます。依頼内容だけを根拠にした既定値が多いのは、既定値に戻っている兆候です。
- 根拠が空欄の行が残ったら、プロファイルの一貫した性格（「4. 要素どうしの関係」）から決められないか見直します。それでも決まらない行があるときだけ、ユーザーに1問聞きます（選択式）。

**参考の値は写さず、比率とルールを写す**: 「本文 15px、数字 44px」→「数字は本文の約 3 倍」。内容（テキスト・用途・業種）が参考と違うのは当然です。ユーザーが変えたいと言った軸（例: 差し色を自分の業種の色に）は、(b) を根拠に値を変えます。ユーザーが触れていなくても、参考の業種・題材に結びついた値（銭湯の緑、パン屋の小麦色など）は、そのまま写す前に今回の内容（素材・業種）と照らし、合わなければ (c) を根拠に同じ明度・彩度の範囲で変えます。

### 記入例（Web。参考＝喫茶店のサイト、お題＝古書店の1ページ）

参考のプロファイル `kansei/kissa-hiyori.md`、ユーザーの言葉「えんじ色は好き。ボタンっぽいのはいらない」、依頼文「買取価格の目安を載せて」「店名は大きく」。

| 軸 | AI の既定値 | 今回の値 | 根拠 | 実物の値 |
|---|---|---|---|---|
| 地色と面積比 | 白 #FFFFFF、全面 | #F3EFE6、90% 以上 | (a) 0.「地色: #F2EEE4 93%」 | #F3EFE6 91% |
| 文字色・差し色と面積比 | #111827、青 #2563EB をボタンに 8% | 文字 #2B2622、差し色 #7A2E2E を 1% 以下（定休日だけ） | (a) 3. カラー「差し色は1か所、面積 1% 以下」、(b)「えんじ色は好き」 | #2B2622、#7A2E2E 0.4% |
| 書体（描画された実体） | Inter＋system-ui、見出し太字 | ゴシック1書体、太さは 400 のみ | (a) 5.「2. 太字を使わない」 | IPAGothic 100%、w400 のみ |
| 本文サイズと行間 | 16px / 1.6 | 15px / 1.9 | (a) 0.「本文: 15px / 1.9」 | 15px / 1.9 |
| ジャンプ率 | 3.0（48px 太字見出し） | 見出しは本文の 1.6 倍、最大は店名で 2.4 倍まで | (a) 2.「1. 見出しが小さい（本文の 1.6 倍）」、(c)「店名は大きく」 | **2.9（店名 44px）→ 違う。36px に直して 2.4** |
| セクション間余白 | 80px（行送りの 3 倍） | 本文行送りの 5〜6 倍 | (a) 3. 配置「セクション間は行送りの 5 倍以上」 | 6.1 倍 |
| 角丸・影 | 角丸 12px＋薄い影 | どちらもなし | (a) 5.「1. 影も角丸も使わない」 | なし |
| 揃え方と左端の揃い | 中央揃え 70%、左端ばらばら | 左揃え、左端は 2 本 | (a) 4.「対比とそろえ: 左端を 2 本に絞る」 | 中央 0%、上位3つで 88% |
| ラベルの言語と形 | 英大文字 "ABOUT" | 和文の短い語、本文より小さく | (a) 0.「ラベル: 和文 11px」 | 和文×4 |
| カード・固定ヘッダー | 3カード、固定ヘッダー | どちらもなし | (a) 5.「3. カードで囲まない」 | カード 0、固定 なし |
| ボタン・リンクの形 | pill の塗りボタン 2 | 下線リンクのみ | (b)「ボタンっぽいのはいらない」 | ボタン状 0、下線 3 |
| 縦書き・数字の組み方 | 縦書きなし、数字は本文と同じ | 縦書きなし、価格は表の右端に揃えて tabular-nums | (a) 0.「縦書き: なし」、(a) 3. 細部「値段は表で右揃え」、(c)「買取価格の目安を載せて」 | 縦書きなし、tabular-nums 6 |

この例で「今回の値＝AI の既定値」の行は無いので、止まる規則には当たりません。「実物の値」が「今回の値」と違ったジャンプ率の行は、手順4で直して測り直しています。

文章・動画・音楽でも同じ形の表を使います。行はそれぞれの分野別ファイルの必須の軸です（文章なら「文の長さ（平均・最長・最短）」「語尾の分布」…）。

## 手順3 作る

- 決定表の「今回の値」を先に変数（CSS 変数・デザイントークン、文章なら「1文 12〜30 字、語尾は〜」のメモ）にしてから作り始めると、途中でぶれにくい。
- 参考作品の文言・画像・ロゴ・固有のモチーフ（参考にしか無い図柄や言い回し）はコピーしません。写すのはルールと比率です。
- 依頼文や資料に無い事実（実績、受賞、お客様の声、数字）を作りません。足りなければ空欄として明示するか聞きます。
- 表に無い判断が出てきたら、既定値で埋めず、表に行を足してから決めます（根拠の規則は同じ）。
- AI っぽさを消すために、理由のないランダムな崩しやノイズを足しません（`references/ai-tells.md` の末尾）。

## 手順4 実物照合

- 参考を測ったのと**同じ道具・同じ数え方・同じ幅**で制作物を測ります。Web なら `measure-web.mjs <制作物.html> --out kansei/img --name made`、文章なら `measure-text.py`。
- スクリーンショットを Read で開いて見ます。数値と目視が食い違ったら目視を採り、食い違いを書きます。
- 「実物の値」が「今回の値」と違う行は、作る途中で既定値に戻った箇所です。直してから測り直します。意図して違えるなら、その理由を (a)(b) の引用で根拠の列に足します。
- **再現ルール同士がぶつかったとき**（例: 文章で「漢字率 26〜29%」と「数字は漢数字」。日付・金額が多いと漢数字が漢字率を押し上げる）: 比率の軸（漢字率・面積比など）は内容の量で動く結果なので、書き方の規則（漢数字、語尾、ラベルの形など）を優先します。比率の行には「今回の値」を内容に合わせて直し、ぶつかった理由を注に書きます。どちらがプロファイルの「2. この作品らしさ」に入っているかが分かれば、そちらを優先します。
- 制作物が測れないもの（音や映像の依頼文・指示書など）のときは、指示書の文面を決定表と1行ずつ照らし、「実物の値」の列に「指示書の◯行目」と書きます。

## 手順5・6 自分に講評をかけて渡す

講評モードを手順1から自分にかけます（手順0の入口の分岐は飛ばす）。渡すときは、照合済みの決定表を「どの要素をどう反映したか」の対応表として添えます。ユーザーがどこを直せばよいか判断しやすくなります。

# 講評

## 手順0 入口の分岐

| 状況 | すること |
|---|---|
| プロファイルと決定表がある（制作の続き） | そのまま手順1へ |
| プロファイルも決定表も無い（人の作品・他の AI の作品の講評、「AI っぽいから直して」） | 「参考にしたい作品はありますか？（あれば場所を／無ければ『なし』）」と**1問だけ**聞く |
| → 参考がある | 学習の手順1（必須の軸を測る）と手順5（AI の既定値・免除リスト）を簡易に行い、仮のプロファイルとして保存してから手順1へ |
| → 参考が無い | 対象の分野の必須の軸ごとに「AI の既定値」をその場で書いて、対象の値と並べた表を作る。ユーザーの不満の言葉（「なんか安っぽい」「AI っぽい」）と `references/ai-tells.md`・`references/principles.md` の「安っぽく見える主な原因」から原因の候補を挙げる。手順2・3はこの表で行う（「参考」の列を「AI の既定値」に読み替え、**既定値と同じ行**をズレとして扱う） |

## 手順1 実物を見る

- Web: `measure-web.mjs` で 1440px と 375px のスクリーンショットを撮り（依頼で別の幅を指定されたら `--widths 1440,375,1280,390` のように足す）、Read で開いて目視します。数値も同じ出力で取れます。
- 画像: Read で開いて見ます。色の面積比は `count-colors.py`。明暗の構図はグレースケールにして見ます（`ffmpeg -i in.png -vf format=gray gray.png`）。
- 動画: `references/video.md` のコマンドでカット検出と代表フレームの一覧画像を作って見ます。音は `measure-audio.py`。
- 音: `measure-audio.py`（スペクトログラム画像も Read で見る）。
- 道具が無い・動かない場合は、その旨を書き、ユーザーに印象を聞きます（選択式で1問）。

## 手順2 並べた1枚を作って見る

参考と対象を左右に並べた1枚を作り、Read で開いて見ます。軸に出ない差（写しすぎ、表示崩れ、密度の違い、全体の温度）はここで拾います。

- Web: `measure-web.mjs --pair <参考> <対象> --out kansei/img`（1440px と 375px の2枚ができる）
- 画像・動画の代表フレーム: `measure-web.mjs --pair <参考.png> <対象.png> --out kansei/img`（画像2枚でも使える）。Playwright が無ければ `ffmpeg -i a.png -i b.png -filter_complex "[0]scale=-1:800[a];[1]scale=-1:800[b];[a][b]hstack" pair.png`
- 文章・音: 測定結果を「軸｜参考｜対象」の2列の表に並べ、参考と対象の冒頭3文（文章）を並べて書き写す

見て気づいた差を3つ以上書きます。

## 手順3 比較表

「要素｜参考｜対象｜ズレ｜修正案」の表を作ります。

- ズレは**印象への影響が大きい順**に並べます。たいてい上位は余白・サイズ比・色の面積比・構造（揃え方・カード・ラベル）・情報量（足しすぎ）で、細部の色味やフォント名は下位になります。
- 修正案は「もっと洗練させる」ではなく「見出しを 32px→24px、本文との比を 2.1→1.6 にする」のように実行できる形で書きます。

## 手順4 点検表で採点

`references/checklist.md` の全項目を、Yes/No ではなく「参考の○○と同じ／違う」の比較で書きます。参考が無い場合は「AI の既定値と同じ／違う」で書きます。免除リストの項目は、参考と同じ使い方なら可、参考に無い場所へ広げていれば修正対象です。

## 手順5 直す

- 影響の大きい順に直し、手順1〜4をやり直します。**最大2周**。2周で残った項目は、ユーザーに「残っている点」として見せ、判断を仰ぎます。
- ユーザーが新しく「これは違う」「ここが好き」と言ったら、原文のままプロファイルの「7. ユーザーの言葉」に追記し、再現ルール・決定表に反映してから直します。抽象的な言葉（「もう少し〇〇っぽく」）は、必須の軸のどの行を変えるかに落とし、変えた行と値を記録に残します。

## 盲検講評（任意）

別のエージェントを起こせる環境では、`--pair <参考> <対象> --blind` で作った1枚（どちらが制作物か伏せたもの）だけを渡し、次を聞きます。

```
左右の2枚は同じ作り手のものに見えますか。違うなら、違って見える点を具体的に3つ（場所と大きさ・色・揃え方などで）。
どちらかが AI に作られたように見えるなら、その理由を具体的に。
```

答えは手順3の比較表に「盲検講評」として足します。`pair-key.txt`（左右の対応）は講評者に見せません。
