# ループ継ぎ目・長時間疲労（loop-fatigue.md）

ループ素材の作り方（定常状態レンダリング）、継ぎ目品質の合議指標、代替手段
としてのクロスフェードの決め方、長時間ループ再生での聴覚疲労のフラグと
差し戻し先。ループの音楽設計（頭尾の進行・エネルギー）は作曲側の担当。
空間系の尾の扱いは references/space.md、継ぎ目の症状からは
references/failure-recipes.md（第5層）。

## 標準: 定常状態レンダリング（3 周描いて 2 周目を切り出す）

- ループ素材は MIDI を 3 周分連続レンダリングし、2 周目だけを切り出して
  納品する。2 周目の冒頭には 1 周目のリバーブ／ディレイ尾が既に鳴っており、
  末尾の尾は 3 周目の冒頭と同一波形になるため、継ぎ目は「作る」のではなく
  構造的に消える。
- 切り出しはサンプル精度（`atrim=start_sample`）で行い、切り出し後の長さが
  仕様サンプル数と一致することを検査する。
- 従来の末尾クロスフェードは、定常状態が作れない場合の**代替に格下げ**する。
- ディレイも同じ扱いで、反復がループ点を跨ぐ前提で連結描画する。
- 時間変調（LFO／フィルタ掃引／リバーブ送り量の変調／ダッキング等）を使う
  場合は、変調周期を**ループ長の整数分の一**（loop_seconds / k、k は 1〜4）に
  量子化し、周期を render_report に記録する（波形の継ぎ目が完璧でも変調位相の
  跳びで継ぎ目が露出するため）。

## 継ぎ目判定（合議制）

判定はファイル単体でなく、**3 周連結した再生波形**の 2 か所の継ぎ目
（1→2 周目、2→3 周目）で行う。単一指標で結論にしない。

| 指標 | PASS | WARN | FAIL |
|---|---|---|---|
| 相対跳び比（継ぎ目のサンプル間差分 ÷ 内部差分の 99 パーセンタイル） | <= 1.0 | 1.0〜1.5 | > 1.5 |
| 多解像度 RMS 窓（10／25／100 ms）の段差 | 3 解像度すべてで相対比が閾値内 | — | いずれかが FAIL 域 |
| スペクトルフラックス比（継ぎ目 ÷ 内部オンセット位置の分布） | <= 1.2 | 1.2〜1.5 | > 1.5 |
| 帯域別段差（オクターブ帯域ごとの前後 100 ms エネルギー差） | 最大 <= 3 dB | — | > 3 dB |
| 位相相関 rho（尾窓と頭窓の正規化相互相関） | >= -0.3 | — | < -0.3（接続点の再探索かフェード長変更が必須） |
| スペクトル重心の跳び（継ぎ目 ÷ 内部平均） | 0.8〜1.25 の範囲内 | 範囲外 | — |
| DC 差／ノイズフロア差 | ノイズフロア差 <= 2 dB | DC 差が -60 dBFS 相当超 | — |

- L／R 各チャンネルと Mid／Side でも測り、**最悪系列の値で判定**する
  （モノラル値も後方互換のため残す）。モノラル合計では相殺されて見えない
  片側クリックや Side の段差を捕まえるため。
- 従来の「クロスフェード済みと素つなぎ（butt）の RMS 段差比較」は参考値として残す。

## クロスフェード（代替時の決め方。固定 2 秒は廃止）

- **カーブは相関で選ぶ**: rho >= 0.5 なら等電圧系（線形の S 字変形または
  sin²/cos²）、rho <= 0.2 なら等パワー（`acrossfade=c1=qsin:c2=qsin`）、
  中間は両方を描いて上の合議指標が小さい方を採用する。
- **長さは探索で決める**: 候補 [50, 250, 500, 1000, 2000] ms から合議指標が
  最小のものを選ぶ。素材別の目安は、ドライで打楽器中心 10〜30 ms、
  ピアノ／ギター等の減衰楽器 100〜500 ms、パッド／長いリバーブ 0.5〜2 秒
  （尾の長さまで）。spec の `loop_fade_ms` で上書き可。
- 採用条件: フェード区間の RMS 偏差が ±0.5 dB 以内、かつフェード区間単独でも
  トゥルーピーク -1 dBTP を満たすこと（相関素材＋等パワーでは中点で最大
  1.41 倍まで増え得る）。
- **ループ化は必ず loudnorm の前に行う**順序を固定する。フェード後に全体の
  TP を再測定する。
- ゼロ交差スナップは同方向の交差に限定し、切り点から ±5 ms 以内とする。
  単独では合格条件にしない（値を 0 に揃えても傾きが逆だと角が残る）。
  ずらした量は render_report に記録する。

## 納品形式とサンプル長検査

- 納品は **WAV／OGG のみ**。デコード後のサンプル総数が仕様どおりかを検査し、
  `|actual - expected| <= 1` サンプルを合格とする。
- MP3 が入力・出力に混ざっていたらゲートで即 FAIL（エンコーダ遅延と
  パディングで先頭・末尾に無音が入り、サンプル精度のループが保証されない）。

## ループ設計側の申し合わせ

- ループ直前に大きな一発物（最終和音の強打・長いブレス）を置かない
  （最も長い尾を作り、継ぎ目で一番目立つ）。作曲側との申し合わせ事項。
- RT60 はループ長の 1/8 以下を目安とし、場面帯（references/space.md）の
  小さい方を取る。
- 非ループ曲では逆に、ファイル末尾に尾が RT60 ぶん残っていること
  （末尾で切れていないこと）を長さの確認に加える。

## 疲労フラグ（measure の出力に持たせる）

`fatigue_flags: {high_freq, dynamic_stasis, short_cycle}` を出す。

| フラグ | 条件 | 直し先 |
|---|---|---|
| high_freq | 4〜16 kHz 帯域エネルギー比が同場面の基準曲より +5pt 超 | マスタリング EQ（高域シェルフ -1〜-2 dB、6 kHz 以上）か、オクターブ重ねの間引きを編成側へ |
| dynamic_stasis | ループ LRA < 3 LU、または 10 分連結版の 30 秒窓ラウドネス SD < 0.5 LU | loudnorm 前段のコンプ緩和か、セクション間のベロシティ差を作曲側へ差し戻し |
| short_cycle | ループ長が推奨帯を下回る（探索系 60〜180 秒／環境系 120〜480 秒が推奨帯） | 音響で直さず作曲側（C7）へ差し戻す。30 秒未満のループは「2 周目以降の差し替え層があること」を納品条件にする |

- 継ぎ目出現回数（600 / loop_seconds 回／10 分）と主題の出現回数を
  render_report に記録し、疲労の入力変数として扱う。
- 周回ごとの微変動の受け皿として、同長・同位相で差し替え可能な層
  （2A／2B 等）を用意できる納品形（ステム分割＋層ごとのループ化）を
  選択肢として持つ。層ごとに継ぎ目判定を通し、層同士の長さ・開始位相が
  サンプル単位で一致することをゲート条件にする。

## 10 分テスト（納品手順に固定）

- 納品前にループを 10 分間（最低 5 周）連続再生し、曲フォルダの memo に
  「継ぎ目に気づいた周回番号／煩わしさ 3 段階」を記録する。
- 機械指標で WARN が出た曲は試聴を必須とする。問題が継ぎ目なら本書の
  クロスフェード／再探索へ、疲労なら疲労フラグの直し先へ差し戻す。
- **マスタリングの最終確認は 10 分以上の休憩後に 1 回だけ**行う
  （長時間聴いた直後の耳は閾値が一時的に上がり、判断が系統的にずれるため）。
