# 検証・環境再現性（environment.md）

レンダリング環境の再現性、golden file 回帰、失敗検出、selfcheck の設計原則。
音響ゲートの中身は loudness.md／eq-masking.md／perceptual.md、症状からの
入口は failure-recipes.md。

## 環境フィンガープリント（environment.lock.json）

- 描画に効く環境要素の実測値を `environment.lock.json` としてスキル内に置き、
  selfcheck が毎回それと照合する。要素: fluidsynth の版、ffmpeg の版、
  Python 本体と mido／numpy の版、OS、使用音源のファイル名と SHA-256。
- 生成はスクリプトで自動化し、手書きしない。render.py は render_report.json に
  manifest のハッシュ（先頭 12 桁）を転記し、どの環境で描いた曲かが後から
  追えるようにする。
- selfcheck は版の完全一致でなく「manifest と major.minor が一致するか」を見て、
  不一致なら ENV_DRIFT として別表示にする（3分類参照）。

## 版上げは golden 再承認イベント

- FluidSynth の版を上げたら、必ず golden 回帰（後述）を回して差分を承認して
  から日常使用に戻す。FluidSynth の変更履歴には既定リバーブエンジンの変更、
  補間方式の変更、最終段へのリミッター追加など「音楽的に破壊的な変更」が
  明示されており、同じ MIDI・同じ音源でも版が違えば別の音になる。
- シンセ設定（サンプルレート・補間方式・リバーブの on/off と
  room-size／damp／width／level・コーラスの on/off と level／speed／depth・
  ゲイン）は既定任せにせず、render.py の 1 か所（設定辞書）に集約して
  全量明示し、渡した設定一式を render_report.json に残す。設定辞書のハッシュも
  manifest 側に含める。値を変える場合は「曲の変更」でなく「辞書の変更」として
  差分が見えるようにする。
- 標準工程のサンプルレートは **44100 Hz に統一**する（SKILL.md 前提節）。

## 道具の恒久配置

- fluidsynth の実体は実験用の一時パスに依存させない。apt のシステム導入を
  正とし、ラッパーが要る場合も配置先は恒久パス（ワークスペース内の
  版つきディレクトリ等）にする。ラッパーは実体へ exec する前に実体の存在を
  確認し、無ければ標準エラーに出して非 0 で終わる。
- selfcheck の道具点検は `which` の有無でなく、**`fluidsynth --version` が
  実働で版を返すこと**と、ラッパー参照先が恒久パスかを見る。

## 音源の同一性（SHA-256）

- 音源の同一性はサイズでなく **SHA-256 と形式ヘッダ**（SF2 は先頭が
  `RIFF`＋`sfbk`）で検証し、台帳（instruments.md）に sha256 と再取得先・
  復旧コマンドを記録する。
- /usr/share の音源は「消える前提」で扱う: Debian パッケージ名・導入コマンド・
  期待パス・期待サイズ・SHA-256 を台帳に明記し、selfcheck の FAIL 時はその
  コマンドを復旧手順として表示する。

## 復旧は冪等な setup スクリプト 1 本

- `scripts/setup_env.sh`（仮称）1 本で環境を戻せるようにする。内容:
  (1) apt パッケージ（fluidsynth、fluid-soundfont-gm、
  musescore-general-soundfont、ffmpeg）の導入、(2) venv の作成と
  mido／numpy の版ピン＋ハッシュつき requirements での導入、
  (3) 音源の配置と SHA-256 照合、(4) ラッパーの配置、
  (5) 最後に selfcheck を実行して結果を表示。
- 各ステップは「目標状態の確認→無ければ実行→再確認」の形にし、**2 回連続で
  実行しても 2 回目は全ステップ no-op になる**ことを受け入れ条件にする。
  スクリプトの最後は必ず selfcheck で、終了コードをそのまま返す。

## selfcheck の 3 分類と報告形式

- FAIL を 3 分類で集計表示する:
  - **ENV_MISSING**: 道具・音源が無い
  - **ENV_DRIFT**: あるが版・ハッシュが manifest と違う
  - **SKILL_BROKEN**: py_compile 失敗、プリセット欠落、台帳不整合
  - （＋TIMEOUT: 外部コマンドのタイムアウト）
- 終了コードも分類で分ける（例: 0 = 全 PASS、2 = ENV_MISSING のみ、
  3 = ENV_DRIFT、1 = SKILL_BROKEN を含む）。
- FAIL メッセージは render.py の preflight と同じ**「項目・状況・復旧手順」の
  3 点セット**で統一する。道具系は setup スクリプト、音源系は台帳の出所と
  再導入コマンドを復旧手順に入れる。
- 台帳と selfcheck の二重管理を解消する第 1 歩として、**楽器名集合が台帳と
  selfcheck で完全一致すること**を selfcheck 自身の点検項目にする
  （台帳から点検対象を生成する形は第 2 歩）。

## 点検の 3 層

| 層 | 内容 | いつ回すか |
|---|---|---|
| 第1層 selfcheck | 存在・版・ハッシュ・試し鳴らし（1 分以内） | 毎回 |
| 第2層 golden 回帰 | 描画＋比較（2〜3 分） | スキル編集後と環境復旧後 |
| 第3層 納品ゲート | 曲ごとの render.py ゲート | 曲ごと |

実行規律: 一時ディレクトリ内で完結し、ネットワークとカレントディレクトリに
依存しない。外部コマンドごとにタイムアウトを付ける（試し鳴らし 60 秒、
golden 全体 300 秒が目安）。失敗時の自動リトライはしない（揺れを隠さない）。
セクションごとの所要時間を末尾に表示する。

## golden 回帰（納品ゲートとは別層）

- 独立スクリプト（`scripts/golden_check.py` ＋ `tests/golden/`）にする。
- コーパスは経路別の短い固定 MIDI の組: (a) GM 各系統の単音・スケール短片、
  (b) 実例仕様書の冒頭数小節相当の短い曲片、(c) 実録 SFZ（カリンバ、チェロ）の
  短片、(d) エレキギター DI の短片、(e) ループ継ぎ目ケース、
  (f) わざと読めない音源を指定する異常系ケース
  （「preflight か無音検出で止まること」自体を期待結果にする）。
  各 5〜15 秒、全体の描画が 2〜3 分以内に収まる量にする。seed は固定する。
- 保存するのは音声でなく、ケースごとの `expected.json`（measure の計測値＋
  framehash＋環境フィンガープリント＋生成日時＋承認理由）だけにする。
  WAV／OGG は毎回生成して捨てる。
- 比較は 2 層:
  - 第1層: 生 WAV のデコード音声に対する framehash（SHA-256）の完全一致。
    OGG のファイルバイト列は比較対象にしない（必ずデコード後の音声で比べる）。
  - 第2層: 計測値と golden JSON の差分判定。許容差は納品ゲートより締める:
    LUFS ±0.5、トゥルーピーク ±0.3 dB、長さ ±0.1 秒、低域比 ±2pt、
    重心 ±5%、ピーク ±0.5 dB。
  - env が golden と違う場合は FAIL とせず ENV_DRIFT と報告し、第2層比較だけを行う。
- **決定性の自己監査を前提に置く**: golden 回帰の最初に、同じ MIDI を別々の
  一時ディレクトリで 2 回描画し、framehash が完全一致するか確認する。
  一致しない場合は golden 比較に進まず「非決定性あり」で止める。
- **更新は明示操作のみ**: 検証モード（既定動作）は絶対に書かない。更新は
  `--update-golden --reason "..."` を明示したときだけ行い、理由なしはエラー。
  更新前に旧値と新値の計測差分を表で表示する。ケース単位で選べるようにし、
  全件一括の無言更新は作らない。

## 失敗検出の拡張

- **区間無音検出**: ffmpeg の silencedetect（noise=-50 dB、d=1.0 を開始値）で
  無音区間を列挙し、「曲の途中にある 2 秒以上の無音」「無音区間の合計が
  全体の 30% 超」を失敗にする。冒頭・末尾の想定内無音は仕様（イントロの入り、
  末尾の余韻）と突き合わせて除外できるようにする。結果は render_report.json に
  無音区間のリストとして残す。
- **ステム／チャンネル単位の有音確認**: 各ステムのピークと RMS を個別に確認し
  （期待するステムは全てピーク > 0.05 相当）、ステレオの左右 RMS 差が 6 dB を
  超えたら警告にする。
- **astats による波形欠陥の点検**: 生描画と完成品の両方に掛け、Peak level、
  Flat factor、DC offset、Crest factor を記録する。開始値（golden コーパスで
  校正して固定する前提）: Peak level が 0 dBFS かつ Flat factor > 0 で FAIL、
  |DC offset| > 0.005 で WARN、> 0.02 で FAIL。
  注: astats はラウドネスを出力しない。PSR 等のラウドネス系は ebur128 の
  フレームログ解析で取る（loudness.md）。
- **不連続ジャンプの記録**: 波形のサンプル間差分の大きな箇所を数え、
  継ぎ目以外の区間で多発する場合は失敗にする。閾値は golden コーパスの
  正常曲の分布で決める。
- **描画成功の 3 点判定**: 描画の成否は (1) 終了コード、(2) 標準エラーの
  パターン（"error"、"Failed to load" 等）、(3) 出力の実測（長さが MIDI の
  想定と ±10% 以内、無音でないこと）の全てが揃った場合だけ成功とする
  （終了コードの意味自体が FluidSynth の版依存のため、単独では根拠にならない）。
  結果は 3 点それぞれ render_report.json に残す。
