# 知覚品質・基準曲マッチング（perceptual.md）

「安っぽい」の分解、基準曲との知覚的な近さの出し方（距離レポート）、
主観評価（目隠し A/B・ABX・簡易 MUSHRA・一対比較）の設計、そして基準曲
マッチングの限界。EQ 処方は references/eq-masking.md、ラウドネス値は
references/loudness.md、音源の表現スペックは references/samples.md。

## ゲートの 2 層化

- **ハードゲート**（納品可能性）: LUFS／トゥルーピーク／長さ／継ぎ目／記譜は
  従来どおり合否を持つ。PLR は由来が配信実務（loudness.md）のため、この層に
  例外として置く。
- **基準距離レポート**（合否を付けない）: その上に、各指標の基準値・実測値・
  差分だけを並べたレポートを必須出力にする。**総合スコアへの丸め込みはしない。**
  知覚指標を合否化すると今度はその数値への最適化が始まるため、距離の形で
  人間の判定に渡す。
- WARN の蓄積と一対比較ログ（後述）を突き合わせ、相関の取れた軸だけを
  将来ハード化する。
- レポートの冒頭に「このレポートは作曲の良し悪しを判定しない」と 1 行入れる。

## 「安っぽさ」の 5 軸（診断シート）

判定コメントは必ずこの 5 軸の言葉で書く（「安っぽい」のままでは修正指示に
ならない）。

| 軸 | 測り方 | 主な処方 |
|---|---|---|
| (i) アタック画一性 | 同一ピッチの連続ノートについて、ノートオン直後 50 ms の波形の正規化相互相関。0.95 以上が 3 回以上連続したら「同一サンプル反復」フラグ | RR 付き実録サンプルへ差し替え／開始位置・デチューンの微ランダム化 |
| (ii) 音色の薄さ | スペクトル統計の分布（spread／skewness／flatness／rolloff の中央値と IQR）。flatness の IQR が基準の半分未満なら「音色が動いていない」フラグ | 音源差し替え（samples.md の効果測定） |
| (iii) ダイナミクスの平坦さ | LRA（基準比）／PLR。多帯域プロファイルと併記 | loudness.md のダイナミクス指標 |
| (iv) 空間の欠落 | 最終ノート後の -60 dB 到達時間と「無音でない尾の長さ」。基準と 0.5 s 以上違えば要確認 | space.md のセンドリターン |
| (v) ステレオ像の不在 | L/R 相関係数（全体と 1 s 窓の分布）と Side RMS / Mid RMS 比（width）。基準との許容は相関の中央値差 ±0.2、width ±15pt。低域（250 Hz 以下）の Side エネルギーが大きい場合は別フラグ（モノ互換性） | ステム化と定位（failure-recipes.md 項目11・12） |

- 多帯域プロファイル（オクターブ帯域のエネルギー比と基準との帯域別差分 dB）は
  eq-masking.md の 7 帯域と共通実装で測る。ここでは測るまでを担当し、補正の
  処方は eq-masking.md へ渡す。

## 描画前に差し戻す条件

- **ベロシティ偏り**: MIDI の主旋律・伴奏について、ベロシティの最頻値比率
  70% 超、または標準偏差 3 未満なら「機械的」フラグとし、描画を続行せず
  差し戻す（描画しても直らない問題のため）。ただし適用は**ヒューマナイズ
  刷新後の生成物に限る**（旧来の既定経路は標準偏差が約 2.3 で全曲が落ちる
  ため）。層境界の跨ぎ方の点検は WARN（samples.md）。
- **タイミング完全量子化**: 全ノート偏差 0 ms は FAIL にせず、「ヒューマナイズ
  段を通したか」の確認トリガーに留める。

## 試聴プロトコル

### 日常の必須（これだけは毎回）

- ラウドネスを揃えた**一対比較**＋判定台帳（taste_ledger）への記録。
- 試聴ファイルは統合ラウドネスを測って差分ゲインを掛け、**±0.1 LU 以内**に
  揃えてから提示する。揃えていない比較結果は記録に残さない（0.2〜0.3 dB の差
  でも品質差として誤認される）。ファイル名に元ファイル名を含めない（目隠し）。

### 節目の判断だけに使うもの

評価者はユーザー 1 人であり、負担が跳ね上がるプロトコルは形骸化する。
次はプリセット昇格・音源差し替えなど**節目の判断だけ**に限定する。

- **ABX**: 描画条件を変えた 2 版について「そもそも聞き分けられるか」を先に
  検証し、聞き分けられない変更は好みの判定に進めない。1 セッション 16 試行を
  標準とし（12 正解で p≈0.038、13 正解で p≈0.011）、結果（n と正解数）を
  判定ログに必ず併記する。試行数は事前に固定する。1 日 2 セッションまで。
- **簡易 MUSHRA**: 明示した基準曲（本人の高評価曲）＋隠し基準（基準曲そのもの）
  ＋アンカー（基準曲を 3.5 kHz ローパスした劣化版、ffmpeg `lowpass=f=3500` で
  機械的に作る）を混ぜ、0〜100 で評定する。隠し基準を 90 未満に付けた
  セッションは捨てる。統計処理でなく尺度の再現性確保として使う。
- **一対比較の蓄積と Bradley-Terry**: （対象ペア・勝者・日付・ラウドネス
  一致済みか）をログに蓄積し、貯まったら Bradley-Terry モデルで各版・各描画
  条件の強さを推定する。最低でも同一ペア 2 回以上、順序を入れ替えて記録する。
  この蓄積が、ソフト指標の閾値を本人の好みに校正する材料になる。

### 差の言語化プロトコル

- 試聴判定の際、自由記述の前に固定語彙から 1〜3 語を選ばせる。判定記録の
  必須欄とする。
- 語彙: AudioCommons 8 属性（**明るい／温かい／硬い／深い／ざらつく／鋭い／
  こもる／響く**）＋ **機械的／平たい／薄い**。
- 客観値と主観語が食い違った場合は**主観を正**とし、食い違いを指標側の
  未確認事項として残す。

## やらないと決めたもの

- **FAD／CLAP 埋め込み距離の単曲ゲート流用**: 埋め込み分布同士の距離であり
  集合評価が前提。使うなら「生成曲集 vs 基準曲集」の分布距離として、
  スキル改善の効果測定（曲集レベル）にのみ使う。
- **PEAQ／ViSQOL 等の参照信号型品質モデル**: コーデック劣化の評価用に設計
  されており、音色の薄さや演奏の機械感への感度は保証されない。採用しない。

## 第 2 弾（導入検証が要る）

- Essentia MusicExtractor の一括抽出（MFCC 13・帯域エネルギー・スペクトル系
  統計・log attack time 等）を baseline の `features` ブロックとして取り込む。
  MFCC は平均ベクトル＋共分散で「音色距離」を見る（同一場面の基準曲に限定し、
  距離そのものに合否は付けない。無音区間のフレームは除外する）。
- MOSQITO の心理音響指標（sharpness／roughness／fluctuation strength）。
  絶対値には dBFS→dBSPL の校正仮定が必要なため、合否でなく**基準曲との差
  専用**にし、校正条件を baseline に記録する。
- AudioCommons 音色モデル（brightness／warmth／hardness／depth／roughness／
  sharpness／boominess／reverb の 8 属性の予測値 0〜100）。単音・効果音寄りに
  作られているため曲全体への適用は近似であり、絶対値でなく基準との差分でのみ
  使う。ピッチ依存性が報告されている属性は移調違いの比較では割り引く。

## 基準曲マッチングの限界（明記）

- 特徴量・埋め込みの近さは「音響的な近さ」であって「曲の良さ」ではない。
- 基準曲は**同場面・同編成カテゴリ**から選び、ファイル名と選定理由を
  baseline に記録する。場面・編成の異なる基準曲へ近づけることを目標化すると
  場面適合を壊す。
- 主題・リズム・対比といった作曲側の問題は音側指標では原理的に検出できない。
  実際、全チェック PASS でも「全然響かない」として却下された実例がある。
  音側が全て基準並みでも却下は起こる。音側の役割は
  「作曲が良いときに、それを安っぽく潰さないこと」と位置づける。
