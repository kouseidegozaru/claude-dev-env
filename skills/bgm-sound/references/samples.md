# 音源・サンプルの表現力（samples.md）

台帳（references/instruments.md）の表現スペック欄の定義、主旋律に使える音源の
足切り、自前レンダラー render_sfz.py の制約と「鳴らない前提の設計」、新規音源の
採用 5 ゲート、音源差し替えの効果測定。台帳そのものは instruments.md、
採用の入口は SKILL.md 手順5。

## 台帳の表現スペック欄（必須化）

台帳の全楽器に次の欄を持たせる。分からない値は推測で埋めず「未計測」と書く。

| 欄 | 内容 |
|---|---|
| 実効ベロシティ層数 | lovel/hivel の区切り数（SFZ）／ velocity zone 数（SF2） |
| RR 数 | seq_length または同音高の region 数 |
| 奏法一覧 | 使えるアーティキュレーションと対応ファイル／プログラム名 |
| サンプリング間隔 | 半音単位（毎半音／全音／短 3 度／5〜7 半音など） |
| リリース有無 | trigger=release 系のリリースサンプルの有無 |
| 遷移サンプル有無 | true legato（遷移そのものの録音）の有無。無い楽器の滑らかな旋律は「sustain の重なり」であって legato と呼ばない |
| 使用 opcode 一覧 | その SFZ が使う opcode の集合（採用時に機械抽出する） |
| ライセンス原文の保存先 | ダウンロード物に同梱された LICENSE／readme の保存先 |
| クレジット文字列 | CC BY の場合に表示する表記文字列 |
| 推奨ベロシティ帯 | 1 層楽器のみ（後述） |
| sha256 | 音源ファイルの同一性検証用（references/environment.md） |
| 復旧コマンド | 消えた場合の再導入コマンド／再取得先 |

## 足切り（用途の制限）

- **ベロシティ層**: 主旋律に使う楽器は最低 3 層、持続系は最低 2 層。
  1 層の楽器は主旋律に使わない（伴奏・打楽器の色付けのみ）。
  層数が分からない楽器は「未計測」として主旋律候補から外す。
- **RR**: 持続系 2〜4、短音系 3〜9、繰り返し打撃が多いものは 4 以上。
  足切りに満たない短音系は「同音反復の多いパートに使わない」と用途制限を書く。
- **移調距離**: 露出するパートではキーセンターから ±2 半音以内を原則とする。
  主旋律の音の 1 割超が外れる場合は、曲の調を移すか楽器を替えることを検討する。
- **1 層楽器の使い方**: そのパートのベロシティ幅を狭い帯（例: 65〜95）に制限し、
  強弱は音量と編成の増減で付ける。humanize の jitter が帯を突き抜けないよう
  ±4 以内に収める。広いダイナミクスが要るフレーズは、そのフレーズだけ層の
  ある楽器へ替える。

## GM 系 SF2 の役割

- GM 系 SF2（FluidR3_GM／MuseScore General／GeneralUser GS）の役割は
  **伴奏・下書き・穴埋め**に限定する。主旋律と露出するソロは SFZ 実録側
  （層・RR 充足組）で描く render_mix 型の分担を既定にする
  （SF2 は RR 巡回や keyswitch のような演奏選択の仕組みを規格に持たず、
  実物も大半が 1〜2 層のため。「GM 一括描画で機械的」はこの上限を主旋律に
  当てた結果でもある）。
- 曲の仕様で「主旋律の描画経路（SFZ 実録／SF2）」を必須記入項目とし、
  SF2 の場合は理由を書く。GM しか無い楽器（金管の多く等）は、露出を避ける
  編成（パッド化、短い合いの手）で使う。
- SF3 は SF2 の圧縮版であり表現上限は同じ、と台帳に注記する。

## render_sfz.py の制約（鳴らないものの一覧）

自前 `render_sfz.py` が解釈する opcode は **sample / key / lokey・hikey /
pitch_keycenter / lovel・hivel / volume / tune / default_path / seq_position
（巡回 RR）の 9 種のみ**。次は SFZ 仕様に存在しても**現行では鳴らない**:

- velocity crossfade（xfin/xfout）
- リリースサンプル（trigger=release、rt_decay）と演奏ノイズ
  （パスに noise を含む region は自動除外される）
- keyswitch（sw_*）
- CC 表現（locc/hicc、xf_locc 系）
- ランダム RR（lorand/hirand）
- ampeg 等のエンベロープ指定

この制約は SKILL.md と台帳の両方に明記する（済み）。これらは第 2 弾の
レンダラー拡張タスクとして切り分ける。

### 鳴らない前提の設計（第 1 弾の代替運用）

- **層境界の段差回避**: 層境界の前後 ±8 のベロシティを仕様側で避ける
  （境界またぎの連続音を置かない）。
- **奏法の切り替え**: keyswitch でなく、奏法ごとに別ステム／別プログラムとして
  描き分ける。目安: 音価 0.35 秒未満 ＝ short 系、以上 ＝ sustain 系、
  跳ねるフレーズ ＝ pizz/spiccato。
- **持続系の音の最中の表情**: note-on ベロシティ＋フレーズ単位の音量設計で
  代替する。ロングトーンは 2〜3 音に分割してベロシティ勾配を付ける／
  フレーズの山に合わせて後段の音量を手で振る。
- **リリースの不自然な切断回避**: render_sfz の fade／tail パラメータ
  （--fade-ms、--tail）を楽器ごとに台帳へ記録し、短い音ほど tail を残す。
- **擬似 legato**: フレーズの繋ぎ目に音量の微ディップ（数 dB・数十 ms）や
  アタックの弱い後続音で繋ぐ。主旋律の歌わせ方が要る曲では、この制約を
  「既知の限界」として先に申告する。
- **RR は巡回（seq）のみ**を使う。描画開始時に RR カウンタをリセットし、
  同音 8 連打のテスト描画を 2 回行って波形が一致することで再現性を確認する。

### SFZ を自作・改変するときの注意（amp_veltrack／velcurve）

層分割と amp_veltrack／amp_velcurve はセットで決める。決めないと、ベロシティ
由来の減衰と層自体の小ささが重なって弱い音が二重に弱くなり、ダイナミクスが
潰れる。既定手順: 各層の最高ベロシティ点で amp_velcurve_N=1 を置くか
amp_veltrack=0 にして、音量は層の録音レベル側で揃える。台帳楽器を改変した
場合は変更点を台帳の備考に残す。

## ベロシティ分布の点検（作曲・音響の共有 WARN）

- 仕様／MIDI の主旋律ベロシティのヒストグラム（最小・最大・四分位）を出し、
  採用楽器の層境界を**少なくとも 2 層以上跨いでいるか**確認する。
  層が 3 つあってもベロシティが 88〜96 に固まっていれば常に同じ 1 層しか
  鳴らない。
- 診断: vel 30／60／90／115 の 4 点で同音を描き、スペクトル重心が単調に
  上がることを確認する。上がらない楽器は「層が音色に効いていない」として
  台帳に記録する。
- フレーズの山では意図的に層境界を跨ぐベロシティ差（例: 平常 70〜85、
  山場 100〜112）を仕様に書く。

## 採用 5 ゲート（新規音源）

既存手順（ライセンス確認→公式 tarball 取得→波形検品→試し鳴らし→台帳登録）に
表現系の 2 ゲートを挿入したもの。**git クローンではなく Release ZIP／公式
tarball で取得する**（バイナリ破損の教訓。guitar.md の検品節参照）。

1. **ライセンス**: 配布サイトの宣伝文でなく、ダウンロードしたアーカイブ内に
   同梱された LICENSE／readme の原文で判定し、そのファイル自体を音源フォルダに
   保存する。ポータル型配布では音ごとにライセンスが違う前提で個別確認する。
   商用可否が文面で確定できないものは「未確認＝使わない」。
2. **公式取得**: Release ZIP／公式 tarball。
3. **波形＋音程検品**: 波形ジャンプ 0、重心 500〜1500 Hz の従来検品に加え、
   各キーセンター音の基本周波数を測り、想定音高から ±15 セント超の音は
   tune 補正してから登録する（補正量を台帳に残す）。
4. **表現スペック棚卸し**: 層数・RR 数・奏法数・サンプリング間隔・リリース
   有無・使用 opcode 一覧を数えて記録する（SFZ のテキスト解析で機械化できる）。
   主旋律の足切りに落ちた楽器は、用途制限付きでなら登録可。
5. **実フレーズ試し鳴らし**: 単音でなく、音階（全音域）・同音 16 連打・
   ベロシティ 4 点・実際の曲の 8 小節フレーズの 4 点セットで描く。
   同音連打の隣接波形相関を**マシンガン検査**として記録する（相関が高い楽器は
   ベロシティを ±3〜6 振る／タイミングを数 ms 振る運用を台帳に書くか、
   RR 充足組へ差し替える）。

## 音源差し替えの効果測定

- 測定は loudnorm 等のマスタリング前（**raw**）・同一ゲイン・同一 MIDI で行う。
  固定の審査用ファイル（音階＋連打＋4 点ベロシティ＋8 小節フレーズ）を使い回す。
- 主指標は表現系: (a) ベロシティ応答 ＝ vel 30／60／90／115 での重心の単調
  増加の有無と幅、(b) 反復分散 ＝ 同音 16 連打の隣接波形相関の平均、
  (c) LRA（ダイナミクス幅）。
- 低域比・重心は「悪化していないこと」の副条件に降格する（編成でほぼ決まり、
  音源差し替えでは動きにくいことが台帳の実測で分かっている）。
- 最終判定は、統合ラウドネスを **±0.1 LU 以内**に揃えた目隠し A/B で行い
  （試行回数は事前に固定する）、勝った場合だけ台帳の既定を変える。
  識別できない／選好が割れた差し替えは「効果なし」として既定を変えない。
  結果（試行数・正答／選好数）は台帳の実測欄に日付付きで残す
  （プロトコル詳細は references/perceptual.md）。

## ナイロンギター候補（未採用・分離表記）

- 従来の「無料・複数層・ライセンス清潔な単音セットが見つかっていない」は
  陳腐化した。第一候補として **Meta Open Sound の Nylon Guitar（CC0、
  348 サンプル、E2〜B5、6 弦ゾーン、3 ダイナミクス層 ＝ ピック 2 層＋
  フィンガー 1 層）** を採用審査へ回す。代替は FreePats Spanish Classical
  Guitar（CC0、SFZ/SF2 あり、ただし 1 層）。
- Meta 側は WAV 素材集で SFZ マッピングが無い前提。弦ゾーンと層から SFZ を
  組む作業（render_sfz.py 対応 opcode の範囲内 ＝ lovel/hivel＋seq のみで組む）
  を見積もってから採用可否を決める。
- リポジトリには CC0 と CC BY 4.0 の素材が混在する旨の記載があるため、
  ナイロン個別のライセンスファイルをダウンロード物の中で確認する。
- **審査を通るまでは台帳に「候補（未採用）」として分離表記し、無断で使わない。**
