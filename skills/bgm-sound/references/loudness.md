# ラウドネスとマスタリング（loudness.md）

統合ラウドネス、ダイナミクス（LRA / PLR / PSR）、納品先ごとの目標値、
アルバム正規化、loudnorm の正しい使い方と、マスター段でやってよい仕事の上限。
ゲートの全体像は SKILL.md 手順4 と references/perceptual.md、帯域の話は
references/eq-masking.md を参照。

## delivery プリセット（納品先で目標を切り替える）

-14 LUFS は Spotify の配信値であって、ゲーム BGM の値ではない。render は
納品先プリセットで目標を持ち、使ったプリセット名を render_report に必ず記録する。

| プリセット | 統合ラウドネス | トゥルーピーク | 用途 |
|---|---|---|---|
| streaming | -14 LUFS ±0.5 | -1.0 dBTP 以下 | 配信プラットフォーム向け |
| game_asset | 作業帯 -18〜-23 LUFS（初期値 -20 ±1） | -1.0 dBTP 以下 | ゲーム組み込み用ファイル |
| broadcast | -23 LUFS ±0.5 | -1.0 dBTP 以下 | 放送系 |

- game_asset の -20 は**未検証の作業値**。ゲームエンジン実機で効果音と一緒に
  聴いて ±2 LU の範囲で確定し、spec の gate に固定するまでは render_report に
  「未検証」と書く。
- ゲーム全体ミックスの参照値として ASWG-R001（ホーム -23±2、携帯 -18±2、
  TP -1 dBTP）があるが、これは全体ミックスの話で、**BGM ファイル単体の
  ゲート値ではない**。ファイル単体にそのまま適用しない。

## 測定の原則

- 測定は**最終符号化ファイル（OGG）**で行う。WAV の数値は参考値に格下げする
  （符号化でトゥルーピーク等が動くため）。
- 曲集は曲ごとに同じ LUFS へ潰さず、**アルバム正規化**にする: 最も loud な曲を
  アンカーにし、全曲に同一オフセットを掛ける。ゲートは絶対値でなく、
  意図したオフセットとの差 ±1 LU で判定する。
- 場面ごとの相対差は spec の `scene_loudness_offset` で持つ
  （昼 0 / 朝 -1 / 夕 -2 / 夜 -4 / 雨 -1 LU。作業値・試聴で校正する）。
- エンジン側の前提（ミュージックバスの位置 -3〜-6 dB、ダッキング 3〜6 dB・
  release 300〜500ms 等）は render_report / spec に記録する。ファイル単体の
  目標はこの前提とセットで決まる。

## ダイナミクス指標（LRA / PLR / PSR）

| 指標 | 定義 | WARN | FAIL | 備考 |
|---|---|---|---|---|
| LRA | ラウドネスレンジ（基準曲との差で判定） | 基準 ±3 LU 超 | 基準 ±5 LU 超 | 出発値。基準の LRA が小さい曲では下側が到達不能になり実質片側ゲートになる（非対称は妥当だが対称と誤読しない） |
| PLR | トゥルーピーク − 統合ラウドネス | 10 未満 | 8 未満 | 出発値、基準曲で校正。由来が配信実務のため、距離レポート化（perceptual.md）の例外としてハード側に置く |
| PSR（最小） | 最も loud な区間のピーク対短期ラウドネス | 9 未満 | 7 未満 | 出典 Dynameter の値域に寄せた値 |
| 最大短時間ラウドネス | 短期ラウドネスの最大値 | 目標 +6 LU 超 | — | 出典 EBU R 128 s1 は +5 LU。本プロジェクトは BGM 向けに +6 LU へ緩和した出発値 |

- LRA が 2 未満は「潰れ／単調」の注記、12 超は試聴注記を付ける。
- **ループ曲の LRA は 3 周連結して測る**: render の流れの中でゲート前に
  3 周連結した測定用コピーを作り、1 周目を捨てて 2〜3 周目で判定する。
  60 秒未満の素材では LRA を合否に使わない。
- PSR と最大短時間ラウドネスの取得は ffmpeg **ebur128 のフレームログ解析**で
  行う（astats はラウドネスを出力しない）。
- モノラル折り畳みとの LUFS 差が 3 LU を超えたら WARN。
  継ぎ目を跨ぐ短時間ラウドネスの段差が 2 LU を超えたら WARN（継ぎ目の詳細は
  references/loop-fatigue.md）。

## loudnorm の使い方（バグと作法）

- loudnorm は 2 パスで使う: 1 パス目で測定し、測定値を使った 2 パス目の
  線形補正で当てる（パラメータ無しの loudnorm は使わない）。
- **第 2 パスの `normalization_type` を必ず回収して render_report に記録する。**
  linear を指定したのに dynamic に落ちていたら WARN/FAIL にする
  （素の LRA が大きい曲では、線形のつもりが無言で動的圧縮に落ちている
  可能性がある既知の罠）。
- LRA 目標は固定値（旧実装の 11）にしない。`measured_LRA`（＝LRA を変えない）
  を渡す。
- dynamic モードは意図した場合だけ許可し、理由を render_report に残す。
- 符号化後のトゥルーピークが上限を僅かに超えた場合は、TP 目標を下げて
  当て直す（梯子は references/failure-recipes.md 項目5）。

## マスターの仕事量予算

マスタリング段で解決してよい量には上限を置く。超えたらマスターでなく素材側を直す。

- 持ち上げは +4 dB まで、削りは -6 dB まで。これを超える補正が必要なら
  描画ゲイン／ベロシティ／該当箇所を作曲・ミックス側で直す。
- 生描画の狙い: 目標の ±4 LU 以内、ピーク -6〜-3 dBFS。
- 最大短時間ラウドネスが目標 +6 LU を超えたら、マスターで潰す前に
  該当小節のベロシティ／単発ピークを作曲・ミックス側で直す。
