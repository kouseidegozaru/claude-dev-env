# 平凡ではないアイディアを出す

## なぜこの手順が要るか

言語モデルにそのままアイディアを頼むと、「もっともらしい＝確率の高い」答えに寄る。
つまり **誰でも思いつく案** が最初に出て、しかも複数案を頼んでも同じ発想の言い換えになりがち。
この手順は、その引力を意図的に外すためのもの。ポイントは3つ:

1. 平凡な案を **先に吐き出させて禁止する**（頭の中にあるうちは必ず混ざる）
2. 発想の向きを **外から強制する**（オペレーターと、乱数で選ぶ遠い分野）
3. 評価で **角を削らない**（「現実的か」で選ぶと平凡な案に戻る）

## 手順

### 0. お題を確かめる

お題・目的・制約（予算、対象者、期限、絶対に外せない条件）を短くまとめる。
足りなくても質問攻めにはしない。決められない点は仮置きして先に進み、仮置きした内容を最後に明示する。
件数の指定がなければ **最終提示は 7 案前後** を目安にする。

### 1. 平凡リストを作って禁止する

このお題で「普通の人・普通のAIが5分で出す案」を 8〜12 個、正直に書き出す。
ここは手を抜かない。平凡リストが薄いと、平凡な案が後半に紛れ込む。

これを **禁止リスト** とし、以降は次も禁止扱いにする:
- リストの案の言い換え・規模違い・組み合わせただけのもの
- 「アプリを作る」「SNSで発信」「AIで自動化」「ポイント制度」「コミュニティを作る」など、どのお題にも出てくる定番の型（お題に本当に必要な場合だけ、ひねった形で使ってよい）

### 2. 当てる発想の材料を乱数で選ぶ

モデルが自分で「ランダムに」選ぶと結局よく知っているものに偏る。**必ず実際の乱数を使う。**

`references/lenses.md` に発想オペレーター一覧と遠い分野の一覧がある。シェルで番号を引く:

```bash
shuf -i 1-24 -n 5   # オペレーターを5つ
shuf -i 1-60 -n 4   # 遠い分野を4つ
```

（`shuf` が無ければ PowerShell の `Get-Random -Minimum 1 -Maximum 25 -Count 5` など）

引いた番号の項目を読み、それぞれをお題に当てる。当てにくい組み合わせほど捨てずに粘る。
無理やりな接続から出た案のほうが、平凡リストから遠い。

### 3. 発散する（量を出す）

オペレーター × 遠い分野 × お題 の組み合わせから、**最低 20 案** を粗く出す。
この段階では実現性を気にしない。1案1〜2行で十分。

さらに遠くへ行くための追加の型（いくつか必ず使う）:
- **主語の入れ替え**: 本来のユーザーではなく、その隣の人・敵・子ども・未来の自分・機械が主役なら？
- **価値の反転**: 欠点・面倒・失敗・待ち時間・不便そのものを売りにしたら？
- **お金の流れの逆転**: 払う人と受け取る人を逆にしたら？ 無料にする代わりに何をもらう？
- **極端な数値**: 1000倍の規模／1秒／100年／たった1人向け／全員向け
- **最悪の案から**: 意図的に最悪の案を3つ出し、それを裏返すか、最悪の中の筋の良い部分を拾う

案が多くて文脈が重いとき、または視点を本当に分けたいときは、サブエージェントを 2〜3 体並列に立て、
それぞれに **別のオペレーターと分野だけ** を渡して発散させてもよい（互いの案を見せないことで収束を防ぐ）。
各サブエージェントには禁止リストを必ず渡す。

### 4. 平凡さを判定して絞る

20案以上それぞれに、次の3つを付ける（頭の中でよい）:

| 観点 | 問い |
|---|---|
| 意外性 | 5人に同じお題を出したら、この案を出す人は何人いそうか？ 2人以上ならボツ |
| 禁止リストとの距離 | 禁止リストのどれかの言い換えになっていないか？ |
| 筋 | 「なぜうまくいきうるか」を1文で言えるか？ 言えないなら奇抜なだけ |

**意外性と筋の両方がある案** を残す。実現性は選ぶ基準にしない（実現の道筋は次で補う）。
残した案どうしが同じ発想の変種なら、1つにまとめて枠を空ける。

### 5. 提示する

次の形で返す。奇抜さを和らげるための前置きや、「現実的にはこちらが無難です」という平凡案への引き戻しは書かない。

```
## お題
（1〜2行。仮置きした前提があればここに書く）

## 除外した「よくある案」
（禁止リストを1行に圧縮して列挙。何を避けたかを見せるため）

## アイディア

### 1. （短い名前）
- 中身: 何をするか（2〜3行）
- 外した常識: どの当たり前を崩しているか
- うまくいきうる理由: 仕組み・心理・経済的な根拠
- 最初の小さな実験: 1週間・ほぼ無料で確かめる方法

### 2. ...
```

並び順は **安全な案→攻めた案** にし、最後の1〜2案は「一番尖っている案」として遠慮なく振り切る。
最後に、ユーザーが深掘りしたい案を選べるよう一言添える（例:「気になる番号があれば、そこから派生案を出します」）。

## 深掘りを頼まれたら

選ばれた案を新しいお題とみなし、手順1から回す。ただし禁止リストには
「元の案をそのまま細かくしただけのもの」を加える。
