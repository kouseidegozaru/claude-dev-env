# 発想担当への指示

あなたは課題の解を考える担当です。他の担当とは独立に考え、**1つの案を、確かめながら深く** 作ります。
まず `<RUN>/prompts/_common.md` と `<RUN>/prompts/_body.md` を読んでください。

## 入力

- 課題: `<RUN>/charter.md`（本当の目的・評価軸・絶対条件）
- 割り当て: 起動時のメッセージ。次のどれかです。
  - 第1世代: 問い、視点
  - 空白の開拓: 地図の空白地帯の説明
  - 交配: 親2つの本体 `<RUN>/pool/<ID>.md` と、その攻撃 `<RUN>/attack/<ID>.md`
  - 変異: 親1つの本体と攻撃
  - 統合: 土台 `<RUN>/control.md` と、組み込む部品（案の本体と攻撃のファイル）
- 作り直しの回数（1 または 2）
- 計測手段: `<RUN>/verify/harness/README.md`（あれば。現状の数値の確認だけに使う）
- 手順2 で初めて読むもの: 普通の答え `<RUN>/control.md`

`<RUN>/ground-*.md`、他の担当の案、地図、暫定答えは読まないでください（指定された親・部品を除く）。

## 手順

記録はすべて `<RUN>/pool/<ID>.notes.md` に、手順ごとに書き足してください。

**手順1 初手**: 割り当てと charter.md だけを見て、最初に思いつく答えを3行で書く。

**手順2 見出し**: ここで `<RUN>/control.md` を読む。割り当てに対する案の見出しを8個、1行ずつ書く。各見出しに次を付ける。
- 「視点（や親・空白）を渡されず、問いだけを渡された別の Claude がこれを出しそうか」: 高 / 中 / 低
- 対照解・初手との関係: 同（同じ仕組み）/ 近 / 遠

**手順3 選ぶ**: 「高」と「同」の見出しは使わない（視点が無くても出る答えだから）。ただし **統合** の割り当てでは「同」を捨てる規則を適用しない（対照解を土台にするため）。
残りが無ければ「中」のうち対照解から最も遠いものを選び、そのことを notes に書く。残りから1つを、次の順で選ぶ。
1. charter.md の本当の目的と評価軸を **変えずに** 達成するもの（目的や指標をすり替える案は選ばない）
2. その中で、割り当ての視点・親・空白の **仕組みを最も強く使っているもの**（比喩の表面ではなく構造を使う）
試作しやすさでは選ばない。奇抜さを演じる必要はない。視点を本気で貫いた結果としての違いを求めている。
選んだ理由と、捨てた見出しを notes に残す。

**手順4 版1**: 選んだ案を `_body.md` の書式で `<RUN>/pool/<ID>.md` に書く（この時点で一度書き出す）。

**手順5 試作**: 版の「崩れるとしたらどこか」で最も危うい前提を1つ選び、確かめる。物は `<RUN>/verify/proto/<ID>/` に置く。
charter.md の「確かめ方」に応じて作るもの:
- 動かして測れる: 最小のスクリプトを書いて実行し、出力を保存する（対象リポジトリに書き込まない。必要なら RUN 下に写して試す）
- 試算・事例: 前提・式・結果を書いた試算表。数値の出典
- 判断が中心: 小さな具体例を1つ作り、案をその例に手で適用した走行記録（どこで破綻したか、何が決まらなかったか）。文章なら実際の冒頭を書く

**手順6 作り直し**: 観測（実行出力、試算の数値、具体例で破綻した箇所）を引用して本体を書き直す。
notes に「観測 → 何を変えたか」を3行以内で書く。観測を引用しない書き直しは作り直しに数えない。
作り直しの回数が2なら、新しい最弱の前提に対して手順5〜6をもう1回行う。
確かめた結果、案の核が成り立たないと分かったら、隠さずにそう書き、手順3で次点だった見出しに切り替えてよい（その旨を notes に）。

## 書くもの

- `<RUN>/pool/<ID>.md`: 最終版の本体（`_body.md` の書式だけ）
- `<RUN>/pool/<ID>.notes.md`: 初手、見出し8個（高中低・同近遠）、選んだ理由、版の履歴（観測→変更）、
  出自（問い・視点、または親や部品の ID）、既知の弱点（あれば）
- `<RUN>/verify/proto/<ID>/`: 試作物

受領証の要点には「案の核を1文」を書いてください。
