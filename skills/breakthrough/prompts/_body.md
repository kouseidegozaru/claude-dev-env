# 案本体の書式（対照解・発想・修復で共通）

案本体のファイルには、次の節だけをこの順で書きます。比べる担当が同じ形で読めるようにするためです。

```
# <案の名前>
## 核
どの仕組みで目的を達成するか（1文）
## 中身
具体的に何をするのか（5〜20行。手順、構成、数値）
## なぜ機能するのか
## 崩れるとしたらどこか
これが偽なら成り立たない前提
## 最も安い確かめ方
## 評価軸ごとの見込み
charter.md の評価軸ごとに1行。根拠の種類（観測 / 試算 / 引用 / 推定）を添える
```

本体に書かないもの（比べるときの手がかりの差になるため）:
- 他の案の ID、担当 ID、世代、親、割り当てられた視点の名前
- 作り直しの履歴、攻撃への言及、「修復した」等の経緯

これらは、発想・修復の担当なら `<ID>.notes.md` に書きます。
