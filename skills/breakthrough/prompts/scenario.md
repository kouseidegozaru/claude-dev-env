# 試走の場面の担当への指示

あなたは、最後に候補の実物を「使ってみる」ときの使用場面を作る担当です。まず `<RUN>/prompts/_common.md` を読んでください。

- 課題: `<RUN>/charter.md`（特に本当の目的・評価軸・確かめ方）

まだ案はありません。どんな案の実物が来ても同じ条件で使えるように、`<RUN>/scenario.md` に次を書いてください。
1. **使い手**: 実物を使うのは誰の立場か（課題の理屈を知らない、実際の利用者の立場）
2. **場面**: 実物を使って行う具体的な作業を1〜2個。入力となる具体的な状況・データ・課題例を、そのまま使える形で書く
   （コードなら入力と実行条件、文書・指示書なら従って行う具体的な作業、事業なら最初の検証で実際に行う手順と相手）
3. **成功条件**: その作業で「目的を達成できた」と言える条件。評価軸ごとに、使った記録から何を見ればよいか
4. **効かないかもしれない立場**: 判断が中心の課題では、どんな案でも割を食いうる利害関係者を1人、場面に入れる（使い手はその立場の反応も書き下す）
5. **模擬になる部分**: この環境で実際には行えず、手で書き下すしかない部分（あれば）

特定の解き方を前提にした場面にしないでください。普通の答えでも新しい案でも同じように試せる場面にしてください。
