# BGM作曲（bgm-compose）

ゲームBGMなどのインストゥルメンタルの「作曲」を担うスキル。作曲仕様書
（調性・BPM・コード進行・構成・メロディ・編成を音符レベルで記述）から
MIDI を生成するまでが担当範囲。生成AIの取り直しと違い、狙った1フレーズ
だけを仕様書の書き換えで確実に直せるのが要点。

音色・レンダリング・マスタリングは姉妹スキル **bgm-sound** が担う。
このスキルの成果物（仕様書と MIDI）を bgm-sound に渡すと音になる。
「曲が悪い」問題はここ、「音が悪い」問題は bgm-sound、と切り分けて直す。

同梱物:

- `scripts/compose.py` — 仕様書（Python の辞書）から MIDI を生成する
- `scripts/check_midi.py` — 記譜上の機械確認（主題の戻り、音域、跳躍）
- `scripts/selfcheck.py` — 作曲側の横断点検（venv・作曲側スクリプトの構文・作曲スモーク・主題選別の校正記録）
- `scripts/theme/` — 主題選別の前段一式（候補生成・校正済み検査器・回収テスト。手順0で使う）
- `scripts/harmonize_template.py` — 単音リードをコードメロディ（和音）に変換する雛形
- `references/patterns.md` — コード進行・伴奏型・構成型のパターン集と作曲技法
- `references/melody.md` — 良いメロディの作り方（モチーフ設計・フレーズの問いと答え・点検表・音楽心理学の規則）
- `references/voice.md` — 声部書法・対旋律・内声（パッドを面から声部へ。最小移動、ガイドトーン、並行禁止、ドロップ2、短9度回避）
- `references/form.md` — 構成・形式・変奏技法（sentence／period、骨格カタログ、変奏の軸、対比の最低2軸、energy_arc、ループ設計の拡張）
- `references/scene.md` — 場面とジャンルの作法（cozy系の基本値、モードで場面の色付け、時間帯の勾配、天気バリアント、環境曲、疲労対策）
- `references/taste.md` — 物差しの運用（判定台帳の付け方、理由のコード化、拒否条件／勾配条件の2層、合格帯の作り方、試聴プロトコルと採否規則）
- `references/failure-recipes.md` — 失敗パターンと修正レシピ（症状名 F-* の固定、診断→処方の早見表、処方の作法と打ち切り規則）
- `examples/` — 仕様書の実例（曲型とループ型）

## 前提（最初に確認する）

- 作曲と記譜確認は mido の入った venv の Python で行う: `~/workspace/midi-bgm/venv/bin/python`
- 環境の移設・復旧直後と、スキル自体を編集した後は `python3 scripts/selfcheck.py`
  で作曲側の横断点検をする（音源・レンダリング側の点検は bgm-sound の
  selfcheck.py）。FAIL があれば直してから作曲に入る。

作業ファイルは曲ごとのフォルダに置く（例: `~/workspace/midi-bgm/<曲名>/`）。
フォルダには仕様書、生成 MIDI、bgm-sound の render.py の出力（完成 OGG と
render_report.json）を残す。

## 手順0（任意の前段）: 主題選別

主題が印象を決める曲（タイトル曲や場面の顔になる曲）では、作曲の前に `scripts/theme/` の
主題選別を通し、主題を1案に絞ってから手順1へ進む。一発の作曲では主題の質に
担保が無いためで、実使用ではこの選別が目隠しで良い主題と平凡な主題を
分離できることを2回実測した（外部の名主題が1〜5位、平凡な対照が14位以下）。

流れ:

1. 初回のみ校正を確認する: `scripts/theme/calibrate.py --out /tmp/calibration_new.json`
   を実行し、結果が同梱の `scripts/theme/calibration/calibration_record.json` と
   一致することを確かめる（同梱の記録は上書きしない。検査器の既定の権限セットも
   同じ記録から読まれる）。
   権限の無い項目（モチーフ等）は警告としてのみ扱い、足切りには使わない。
2. 初回のみ回収テストで自分の選別を検証する: `scripts/theme/recovery_test.py` で
   目隠しプールを作り、譜面だけを見て全順位を付け、理由をファイルに固定してから
   採点する。名主題が上位に回収できなければ、その選別は未検証として扱い、
   主題選別に頼らない。
3. 候補を30〜60案生成する（`scripts/theme/generate_pool.py`）。手書きの主題も種として混ぜてよい。
4. 権限のある検査器で足切りする（`scripts/theme/theme_check.py`）。
5. 残った候補を、出自を隠した譜面シート（`scripts/theme/theme_sheet.py`）だけを見て
   順位付けし、本命1案と予備を理由つきで記録してから対応表を開ける。
   代理スコアで代用しない。
6. 選ばれた主題を手順3の仕様書の主旋律として書き、手順1以降は通常どおり進める。
   選別の記録（順位と理由）は曲のフォルダに残す。

適用範囲: 校正は長調の主題曲のみ。短調・環境曲では主題選別を使わず、
手順1から通常どおり作る（校正試料の追加が今後の課題）。

## 手順1: 仕様決定

場面ごとに、作り始める前に仕様書へ固定する:

- 長さの目安、ループ有無、BPM、調性、コード進行、構成（各セクションの小節数）、楽器編成
- 場面曲では **mode**（旋法）と場面の**感情語**を1つ書く（scene.md: モードが場面の
  色を決め、感情語が季節ごとの選択を一貫させる）。セクションごとの密度・音域・
  使用パートの目標は **energy_arc** として仕様書の先頭に表で置く（form.md）。
- 場面の物差し（拒否条件と目標ゾーン）は `references/taste.md` で確認してから
  仕様を固定する。既存の合格帯がある場面では、帯の側に倒れた仕様にしない。
- **seed 欄は必須**。乱数の種を記録しない仕様書は不完全として扱う（compose.py がエラーにする）。
  同じ仕様書からはバイト一致の MIDI が再生成できる。
- 同場面の既存曲がある場合は基準として計測し、統合ラウドネス・低域エネルギー比・
  スペクトル重心を仕様書の近くに転記する。計測は bgm-sound の道具で行う:
  `python3 ~/workspace/custom-skills/bgm-sound/scripts/measure.py <既存曲.ogg>`
- 低域エネルギー比は音源ではなく編成でほぼ決まる。基準に寄せる必要がある場合は、
  ベースの音域・密度・持続を仕様の段階で合わせておく（patterns.md の「ベース型」参照）。

仕様書の形式は `examples/spec_spring_noon.py`（曲型）と `examples/spec_loop_lake.py`（ループ型）。

## 手順2: 骨格選択

`references/patterns.md` から実績のある型を選ぶ。進行・伴奏型・構成型を場面に合わせて組み合わせ、
迷ったら「場面→出発点の目安」の表から始める。型に無い進行を書くのは構わないが、
その場合は理由を仕様書のコメントに残す。
骨格と主題の内部構造は `references/form.md` のカタログから選ぶ（sentence／period、
binary／ternary／aaba／rondo／variations）。変奏を並べる場合は「変える軸は
1変奏につき1つ」を宣言し、隣接セクションの対比は最低2軸で作る。

## 手順3: 作曲

メロディと各パートを音名（MIDI ノート番号）＋拍位置の表として仕様書に書き、MIDI 化する:

```
~/workspace/midi-bgm/venv/bin/python scripts/compose.py spec.py song.mid
```

- **主旋律は `references/melody.md` の手順で設計してから表に書く**（モチーフ先行、
  フレーズは問いと答え、最高音は1回だけ、順次：跳躍＝7：3、跳躍後は反対方向へ順次）。
  書き終えたら melody.md の点検表で数えて確認する。主題が顔になる曲では手順0の
  主題選別と併用する（選別で残った主題を、この型にはめて展開する）。

- 伴奏・ベース・パッドは進行から自動生成される。主旋律は小節ごとの表で書く。
- パッドと内声の配置、対旋律を書く場合は `references/voice.md` の規則に従う
  （最小移動で声部を接続し、対旋律は主旋律の隙間でだけ動かす）。場面の色付けと
  疲労対策は `references/scene.md`（モード、時間帯の勾配、10分テスト）。
- ベロシティの強弱と微小なタイミングの揺らぎが seed で再現可能な形で入る。
- 単調さ対策（作曲技法調査を反映。詳細は patterns.md）: 伴奏は
  `pattern_cycle` で小節ごとにローテーションし、ベースは全音符型を既定にせず
  `root_5_8`／`approach` 等のパターンを使い分ける。仕様書に `ornament` を書くと
  主旋律へ経過音・刺繍音の装飾パスが掛かる。和声は予算制でセカンダリードミナントと
  借用和音を少量差し込み、パッドは 7th/add9 の色音を分担させる。
- 記譜の確認: `~/workspace/midi-bgm/venv/bin/python scripts/check_midi.py spec.py song.mid`
  主題の冒頭フレーズが再現部に逐語で戻っているか、音域と最大跳躍を機械確認する。

## 手順4: 試聴と部分修正

音にする工程（レンダリング〜納品ゲート）は bgm-sound の render.py が担う。
仕様書と MIDI を渡して完成 OGG を受け取り、試聴して直す:

```
python3 ~/workspace/custom-skills/bgm-sound/scripts/render.py \
    --spec spec.py --mid song.mid --out out --name song [--baseline <既存曲.ogg>] [--loop]
```

- 直したい箇所は仕様書の該当フレーズ（数小節）だけを書き換えて、手順3→4を再実行する。
  再生成は数十秒で終わるため、試聴→修正の反復を前提とする。
- 試聴判定は必ず `references/taste.md` の運用で判定台帳に記録する（判定・理由の
  原文・理由コード）。却下された場合は、まず `references/failure-recipes.md` の
  症状名（F-*）で失敗を切り分けてから処方に入る。主題自体が却下されたら処方を
  打ち切り、手順0の主題選別に戻る。
- 修正前と修正後の両方の OGG と仕様書を残し、何を変えたかをフォルダのメモに1行残す。
- 差し戻しの切り分け: 記譜・メロディ・編成の問題はこのスキル（手順3）へ、
  音量・帯域・音色など音響の問題は bgm-sound へ。bgm-sound の納品ゲートが
  外れた項目をどちらに差し戻すかも、この切り分けで判断する。

## ループ型の設計（作曲側）

- ループは「円環」として設計する: 最終小節を V や経過和音で終え、継ぎ目を跨いで
  1小節目の I へ解決させる（patterns.md のループ型、form.md のループ設計の拡張）。
  標準は16〜32小節＋内部のエネルギーの弧で、主題型ループは最低32小節を目標にする。
- ループ型の曲を初めて作るときは、試作1曲で継ぎ目を計測してから本番に入る。
- 継ぎ目の処理と計測（クロスフェード・段差の判定）は bgm-sound 側の担当
  （render.py --loop）。段差が残る場合は、まず設計（頭尾の進行とエネルギー）を
  見直し、それでも残れば bgm-sound 側でクロスフェードを伸ばす。

## 記録

- 曲ごとに、仕様決定から納品までの実時間と手戻り回数を render_report.json とメモに残す。
- 所要の目安は「仕様決定から初回レンダリングまで1曲15〜30分、部分修正は1回あたり数分」
  だが、これは最も易しい場面1曲だけの試算である。場面ごとの実測で目安を更新する。

## 既知の限界

- 声部書法・対旋律・形式・場面の知識は references（voice.md／form.md／scene.md）に
  揃えたが、compose.py の自動生成への組み込み（パッドの声部接続の探索、対旋律の
  自動生成、check_midi.py の点検項目の拡張）は未実施。当面は仕様書を書くときの
  設計規則として使い、組み込みは改善計画のフェーズ2・3で扱う。
- メロディの記憶性は最終的に作曲そのものに依存し、定型化だけで保証はできない。
  主題の戻りは機械確認できるが、良い主題かどうかは試聴で判断する。
  手順0の主題選別はこの担保を強めるが、校正済みの範囲は長調の主題曲のみで、
  選別の余裕は選ぶ側の譜面読みに左右される。
- 音の質感そのものの限界（無料音源の天井など）は bgm-sound 側の「既知の限界」を参照。
  作曲側でできるのは編成と音域の設計までで、低域比のような基礎体力は
  編成で決まる一方、1音の実在感や表情は音源側の担当である。
