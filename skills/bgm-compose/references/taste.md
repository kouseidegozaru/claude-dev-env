# 物差し（taste）— 判定台帳・合格帯・試聴プロトコルの運用

ユーザーの好みを「下限チェックの集まり」でなく「分布の帯＋拒否条件」として
持つための運用ファイル。機械点検と納品ゲートを全部満たしても却下される曲は
実際に起きる（全チェックPASSでも「響かない」で却下された実例がある）。
その失敗は、好みの分布（帯）も、却下側との対比も、判定の記録様式も
無かったために起きた。このファイルはその3点を運用として固定する。

物差しは次の3点セットで1つとし、どれか欠けたら未完成として扱う:

1. **判定台帳**（CSV、1行1判定）— 全ての判定の正本
2. **このファイル（taste.md）** — 台帳から集計した規則・軸・帯への参照
3. **コーパス計測レポート** — 採用/却下コーパスから自動生成した帯の表

置き場は運用側で固定する（台帳とレポートは曲の作業フォルダ群と同じ場所に置き、
将来の支援ツールとも同じ CSV/JSONL 形式で共有できる形にする）。

## 判定台帳の運用

試聴判定は taste.md へ直接書き足さず、まず台帳に1行記録してから集計する。
列は固定する:

| 列 | 内容 |
|---|---|
| id | 台帳内の通し番号（曲名や作品名は使わない） |
| date | 判定日（不明な過去分は「不明」と書く） |
| season / time / weather | 場面カテゴリ（季節・時間帯・天気） |
| conditions | 条件タグ（生成経路・スキル版・音源・レンダラ） |
| verdict | 判定（採用／良い／微妙／却下の4値） |
| reason_text | 理由（ユーザーの言葉をそのまま） |
| reason_codes | 理由コード（後述。症状名 F-* と軸コード） |
| memorable | 主題を口ずさめるか（Yes/No） |
| relisten | 再聴したいか |
| timbre_caused | 音色起因フラグ（「音が悪い」が理由なら1。作曲側の集計から除外し、音色側へ回す） |
| note | 出典・確度（記録あり／記憶ベース・要確認 など） |

- 記入漏れがある行は集計対象外とし、**台帳の有効行数がそのまま判定サンプル数 n** になる。
- 理由の原文を残すのは、後段のコード化の入力になるため。結論だけ残さない。
- 過去分を遡って入れる場合は、原記録で確認できないものを「記憶ベース・要確認」と
  備考に明記し、確認が取れるまでは帯の確定根拠に数えない。

## 理由のコード化（好みの軸の作り方）

判定が10件溜まるごとに1回、理由原文をテーマ分析でコード化する
（読み込み→初期コード付与→テーマ探索→見直し→定義・命名→報告の6フェーズ）。

- 「暗い」「寂しい」「忙しい」「まとまりがない」等の生の言葉を、再利用可能な
  コード（例: 明るさ不足／密度過多／主題の識別性不足／反復不足）に束ねる。
- **出現2回以上のコードだけを正式な軸**とし、1回だけのものは「仮説コード」に分ける。
- 新コードは「定義（である／でない）＋代表原文1件」を添えて軸一覧に追加する。
- 作曲の失敗症状については failure-recipes.md の症状名（F-無顔／F-単調リズム／
  F-散らかり／F-対比なし／F-暗い／F-寂しい／F-忙しい／F-平坦／F-土台却下）を
  そのままコードとして使う。

## 2層構造: 拒否条件（veto）と好みの勾配

taste.md の規則は2層に分ける。全部を連続指標の足し算で扱うと、致命的な1点が
平均に埋もれるためである。

- **上層 = 拒否条件（veto）**: 1つでも当てはまれば却下になる条件
  （例: 暗い、寂しすぎる、忙しい＝高密度で休符が無い、主題が思い出せない）。
- **下層 = 勾配条件**: 程度の問題として効く条件（例: 明るいほど良い、
  モチーフ再現が多いほど良い）。

check への接続は上層から先に行う: 拒否条件に対応する指標（リズム型の種類数、
主題冒頭の音階断片など）は「1つでも外れたら FAIL」、勾配条件は
「帯からの距離で WARN」と判定の重さを変える。却下理由はまず上層への
追加候補として検討し、2回再現したら正式な拒否条件に昇格させる。

## 双極尺度と目標ゾーン

各軸は「暗い⇔明るい」「寂しい⇔温かい」「忙しい⇔ゆったり」のような双極尺度で
書き、判定時に -2〜+2 の5段階を併記できるようにする。加えて音楽感情の標準枠
である valence（快-不快）と arousal（活性-沈静）の2次元に全曲をプロットし、
好みをゾーンとして持つ。運用目安（本スキル側の目安であり原典の数値ではない）:

- 目標ゾーン: valence +1〜+2、arousal -1〜+0.5（5段階換算）
- 「優しくて明るい」は高 valence × 低〜中 arousal、「忙しすぎる」は高 arousal 側への
  逸脱、「寂しすぎる」は低 valence として、別々の直し方が必要な失敗を分離する。

ゾーン外の曲は理由コードと突き合わせ、どの軸で外れたかを台帳に残す。

## 合格帯の作り方

### コーパスの定義

- **高評価コーパス**（良い〜採用と判定された曲）と**却下コーパス**（微妙・却下の曲）を
  対で定義する。登録条件は「台帳に判定があること」。
- 両方に同じ計測スクリプト・同じ対象（**主旋律トラックのみ**、伴奏を混ぜない）を
  適用する。MIDI を持たない生成経路の曲は旋律特徴の対象外とし、音響特徴とは
  分けて扱う。
- 全チェックPASSでも却下された実例は、却下コーパスの確定メンバーとして必ず含め、
  帯の受け入れテスト（後述）のアンカーにする。

### 測る特徴量（固定セット）

場当たり的に増やさず、次の固定セットで回す: 音域（半音）／音高の種類数／
順次率と跳躍率（音程ヒストグラム）／最大跳躍／跳躍後の反転率／最高音の回数と
位置（曲長に対する%）／音数密度（小節あたり）／音価の種類数と nPVI／
同一リズム型の最長連続／モチーフ（冒頭2小節の音程列）の再現回数／
フレーズ末音の度数分布。加えて密度・平均ベロシティ・音域中心は**セクション別の
対比量**（B−A の差、最大/最小セクション比）でも持つ。曲全体の平均だけでは
「B が A と同材料・同密度で対比なし」の失敗を原理的に検出できないためである。
特徴量を追加する場合は、追加理由（どの却下コードと対応するか）をここに記録してから追加する。

### 帯の統計

- 帯は平均±SD ではなく**中央値と四分位範囲（IQR）**で作る。第1四分位〜第3四分位を
  「目標帯」、10〜90パーセンタイルを「許容帯」とする。小標本では平均±SD は
  外れ値1曲で大きく動き、存在しない「平均的な良い曲」への圧力を作るため使わない。
- **全ての勾配指標の帯は両側の閉区間**にする（下限チェック化の禁止）。
  「多いほど良い」と誤解しやすい指標（順次率、モチーフ再現率、同一リズム型の
  連続、音数密度）には、却下コーパスの実測から上限を設定する。
- 帯の表はこのファイルに手書きせず、コーパスから自動生成した計測レポート
  （`band, band_ci95, n` を必ずセットで出す）に置き、ここには生成日と
  コーパス件数だけを記録して参照する。
- 各帯の端にはブートストラップ信頼区間（リサンプル10,000回を標準）を併記し、
  **区間幅が帯幅より大きい特徴量は「未確定（データ不足）」と表示して合否に使わない**。
  n が小さい間（目安: 片側5曲未満）は帯を作らず、観測された最小〜最大を
  「暫定帯」として広めに取る。

### 帯の受け入れテストと判別力による選別

- 帯は、却下コーパスのアンカー実例（全チェックPASSでも却下された曲）が
  少なくとも1つの指標で帯の外に出るか、複合条件（例: 順次率の高さ＋占有率の
  高さ）で捕まえられることを受け入れテストとする。通らない帯は check に組み込まない。
  なお順次率は新計数（音階ステップ差）では却下実例が帯の内側に入りうるため、
  単独の足切りには使わず WARN＋複合条件の位置付けとする。
- 特徴量ごとに採用側と却下側の分布を比べ、効果量（Cliff's delta）で判別力を
  順位付けし、**判別力上位の最大7指標だけを正式な帯として check に接続**する。
  それ以外は診断用の参考表示に留める。順位が入れ替わったら帯の変更として
  変更履歴に残す。

### check 接続と分類器採点の開始条件

- **却下・採用とも各10曲**に達するまでは、合格帯の check 接続は開始しない。
- チェック全体を分類器として採点する場合の定義: 感度 = 却下曲を何らかの
  FAIL/WARN で捕まえる割合、特異度 = 採用曲が FAIL なしの割合。WARN を捕捉に
  含めるかは事前に固定する。各10曲に達するまでは、分類器採点は合否ではなく
  参考表示に格下げする。

## 版管理（仮説→確定）

- 各規則は書式 **「規則文｜状態｜根拠（台帳IDと日付）｜反例」** の4列で書く。
- 新しい判定パターンは「仮説」として入り、同じ方向の判定が独立した曲で
  **2回以上再現したら「確定」に昇格**、反対の判定が出たら即座に「仮説」に戻す。
- 変更履歴は末尾に残し、版番号を上げる。旧版は履歴として残す。

### データ量による段階

- **判定20件未満**: 単変量の対比表（中央値の差と Cliff's delta）で運用する。
  採用確率モデルは作らない。
- **判定20件超**: 特徴量→採用確率の説明モデル（正則化つきロジスティック回帰、
  特徴量は判別力上位3〜5個、検証は leave-one-out 交差検証）を有効化する。
  係数の符号が軸の向きと矛盾する場合は、モデルではなくデータ
  （コーディング漏れ）を疑う。LOOCV の AUC が 0.5 付近なら「まだ特徴で好みは
  説明できない」と正直に記録する。
- **能動的クエリ選択**も20件超で有効化する: 次に聴かせるペアはランダムに出さず、
  モデルが一番迷うペアを優先する。1セッション最大5ペア、内訳は
  「不確実ペア3／帯の端を試すペア1／再現性チェック用の重複ペア1」の固定枠。
  モデルが無い初期は、帯の端に近い曲同士を不確実ペアの代わりにする。
  曲同士の順位は pairwise 結果から Bradley-Terry モデルで潜在スコア化し、
  アンカー曲を 0 とした相対値で記録する（比較には必ず既知の基準曲を混ぜ、
  比較グラフを連結に保つ）。

## 試聴プロトコル

### 日常の必須（これだけは毎回）

1. **ラウドネスを揃えた一対比較**: A/B の2曲は題材（コンセプト・BPM・調性・長さ
   ±5%以内）を揃え、同一音源・同一条件でレンダリングし、統合ラウドネスを
   **±0.1 LU 以内**に揃えてから、出自が分からない形で提示する
   （0.2〜0.3 dB の差でも音質の差と誤認されるため、納品ゲートの ±0.5 とは別物）。
   提示順（AB/BA）はランダム化し、セッション全体でカウンターバランスする。
   どの順で聴いたかも台帳に記録する。
2. **判定を台帳に記録**する（判定・理由原文・コード・覚えられたか）。

### 節目の判断だけに使うもの

- **ABX（16試行を標準）** と **簡易 MUSHRA**（明示基準＋隠し基準＋3.5 kHz
  ローパスのアンカー）は、プリセット昇格・音源差し替え・パイプライン変更など
  節目の判断だけに限定する。日常の全曲判定には使わない（負担が大きく形骸化するため）。

### セッションの妥当性チェック

- 各セッションに、既に高評価が確定している**アンカー曲**1曲と、同一ファイルの
  **隠し重複**1組を紛れ込ませる。アンカーが低く判定された回、重複の判定が
  割れた回は、そのセッションを「条件不良」として帯・モデルの更新に使わない
  （記録は残す）。
- 判定の再現性は物差しの信頼性そのものとする。単純一致率 80% 未満または
  Cohen's kappa 0.6 未満が続く場合は、帯の更新を止めて判定条件
  （疲労・音量・場面の不一致）を先に点検する（数値は心理測定の一般的な
  解釈帯に基づく運用値）。

### 変更検証と採否規則

- 変更は**1回に1変数**だけ（リズムか、音高か、和声か、音域か、密度かの1系統）。
  変えた内容・A/B結果・理由原文・機械指標の前後を台帳の検証記録に残し、
  負けた変更は差し戻す（差し戻した事実も消さずに残す）。
- 採否規則（運用規則であり統計的有意ではない）: **仮採用 = 3題材連続で選ばれる、
  本採用 = 5題材中4勝以上、3勝は5題材追加して再判定、2勝以下は差し戻し**。
  統計的有意を主張するのは16ペア以上のデータが溜まってから
  （目安: 16試行なら12勝で p≈0.038）。
- **主題段階の A/B は別セッション・別記録**にする: フル曲ではなく主題区間だけを
  同一ピアノ音源・同一テンポで切り出した15〜20秒の刺激で比べ、編曲と音色の
  影響を排除する。本編の判定結果は主題のスコアに混ぜない。

## 現在のブートストラップ状態

- 台帳の初版は既知の判定のみで作った（場面カテゴリ＋判定＋理由コードで記録し、
  曲名・作品名は使っていない）。内訳は「良い」が夏の朝・昼・夜の3件、
  「却下」が初夏の朝（記録あり）と春の朝（記憶ベース）の2件、
  「微妙」が秋の昼・夕の2件。
- **現時点では全ての場面で高評価曲が3曲未満**（場面ごとに最大1件）しかない。
  したがって場面別の帯は作らず、全ての帯は**暫定・試聴較正待ち**とする。
  帯が確定扱いになるのは、場面ごとに高評価曲が最低3曲そろい、かつ
  check 接続の開始条件（却下・採用とも各10曲）を満たしてからである。
