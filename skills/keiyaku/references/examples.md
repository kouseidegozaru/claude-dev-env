# 頑健さの例（数字は keiyaku.py の出力）

## 1. B2B で月の受注8件（小母数 → 合算と失注理由）

月次 リード60 → 商談20 → 提案12 → 受注8。funnel は提案・受注に n<30 を付け、順位に入れない。
3か月合算（180 → 60 → 36 → 24）を `--pooled 3 --churn 0.015 --months 12` で再実行すると全段30以上。
target（自社の過去最良）到達時の増分は 商談 +1.6／提案 +1.3／受注 +1.0 件/月（期限時点 +18／+15／+11）と差が小さい。
→ 率だけで決めず、直近の失注10件のメモを読む。「稟議で止まった」が多ければ提案→受注（稟議資料）、
「担当者止まり」が多ければ商談化（決裁者の同席）を1位にする。理由が割れたら増分の大きい商談化。
合算しても30未満なら順位は出さず「定性で決定」と書く。

## 2. 教室で体験枠が満杯（容量の段 → 枠を増やす）

3か月合算 問合せ180 → 体験72 → 入会42。体験枠は月24で毎月埋まり、待ち・断りが3か月で30件。
CSV の体験に `cap=72, wait=30` を入れ `--pooled 3 --churn 0.03 --months 6` で回す。
→ 体験は「上限到達」。体験率を 40%→50% にしても増分0（チラシで問合せを増やしても0）。
「体験の枠を増やす」+5.8 件/月（期限時点 +32）が1位、入会率 58%→65% は +1.6 件/月で2位。
施策は「土曜午前に体験枠を4つ足す（講師1名・担当を決める）」。定員が埋まる教室では入会の上限も cap に入れる。

## 3. 売上目標で決済 CSV だけ（stock で期限時点 → 新規か解約減か）

決済 CSV から: 月初の有効契約 1,200、新規 60/月、解約 60/月（5%、うち決済失敗 20）、ARPU 4,000円。
目標は12か月後の月商 +20%（480万 → 576万円 ＝ 有効契約 1,440）。
`stock --active 1200 --new 60 --churn 0.05 --months 12 --target 1440 --arpu 4000`
→ そのまま 1,200（定常 1,200、差の90%が埋まるまで約45か月）。単独で届くには 新規×1.44 か 解約率×0.61。
新規×1.2 で 1,310、解約率×0.8 で 1,316、両方で 1,432（月商 573万円）。
決済失敗20件を半分にすると解約率×0.83 で +96（新規×1.2 の +110 に近く、手間は小さい）。→ 1位「決済失敗の通知と再決済」、2位「新規 +20%」。
両方でも 1,440 にわずかに届かないので、届かない幅と前提を目標の持ち主に先に伝える。
