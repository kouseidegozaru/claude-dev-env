# 契約数の式とファネル

## 1. 契約数の式

有効契約数（ストック）は毎月こう動く。

```
有効契約数(翌月) = 有効契約数(今月) + 新規契約数 − 解約数
新規契約数       = 流入数 × 段階1の転換率 × 段階2の転換率 × …
解約数           = 有効契約数 × 月次解約率
定常状態         = 月の新規契約数 ÷ 月次解約率
```

- **定常状態**は「このまま続けたら行き着く上限」。現在値が定常状態に近いなら、新規を増やすか解約を減らさない限り伸びない。
- 掛け算のファネルでは、どの段階を相対 10% 改善しても新規契約は 10% 増える。だから「どこが効くか」は**改善の余地（目標値との差）**と**改善のしやすさ**で決まる。`keiyaku.py funnel` は CSV の `target` 列（目標値）までの増分を出す。
- 新規 +10% で定常状態は 1.10 倍、解約率 −10% で 1/0.9 ≒ 1.11 倍とほぼ同じ。違うのは届くまでの速さ（新規増は直後から効き、解約減は母数が大きいほど効く）と費用。`keiyaku.py stock --new-x 1.1` と `--churn-x 0.9` を並べて比べる。
- 目標が売上なら、契約数 × 単価（ARPU）。単価アップ（上位プラン・年払い・オプション）も選択肢に入れる。年払いは解約率も下げやすい。

## 2. 段階の切り方（売り方別）

段階は「計測できる行動」で切る。計測できない段階は推定と書き、計測を施策に入れる。

| 売り方 | 段階の例 |
|---|---|
| セルフ申込（B2C の通販型サブスク・アプリ課金） | 広告表示 → LP 訪問 → 料金ページ閲覧 → 申込開始 → 申込完了 → 初回利用 → 2か月目継続 |
| 無料トライアル → 有料 | 訪問 → トライアル登録 → 有効化（初回の価値体験＝アハ体験）→ トライアル終了 → 有料転換 → 継続 |
| フリーミアム | 訪問 → 無料登録 → 定着（週次利用）→ 上限到達 → 有料化 → 継続 |
| 営業経由（B2B） | 流入 → リード（資料請求・問い合わせ）→ MQL → 商談化 → 提案 → 受注 → 導入定着 → 更新 |
| 店舗・来店型（教室・ジム・通信店頭） | 認知 → 問い合わせ・予約 → 来店・体験 → 申込 → 初月継続 |

- 「有効化」「定着」の定義は、継続している顧客がやっていて解約した顧客がやっていない行動から決める（例「登録後 7 日以内にプロジェクトを 3 つ作った」）。データがあれば、継続群と解約群で行動を比べる。
- チャネル別（検索・SNS・紹介・営業など）に転換率が大きく違うことが多い。内訳があれば、合算の前にチャネル別に表を作る。

## 3. 指標の定義（言葉を揃える）

| 指標 | 定義 | 注意 |
|---|---|---|
| CVR | 段階の通過数 ÷ 前段階の数 | 分母をどこに取ったか必ず書く（訪問比か申込開始比か） |
| 月次解約率（チャーン） | 当月解約数 ÷ 月初の有効契約数 | 新規の月内解約を含めるか決めて書く。年契約は月換算しない |
| 継続率（コホート） | 開始月ごとの N か月後の残存率 | 解約率より原因を探しやすい。初月に大きく落ちるなら期待とのずれ |
| CAC | 獲得費用 ÷ 新規契約数 | 人件費を含めるか書く |
| LTV | ARPU × 粗利率 ÷ 月次解約率 | LTV ÷ CAC が 3 前後以上だと獲得に投資しやすい、が通説。業種で違う |
| NRR | 既存顧客の 12 か月後の売上 ÷ 12 か月前 | B2B で上位プラン・席数増を見る |

## 4. データが無いときの仮置きの目安

**実データがあれば使わない。** 業種・価格・チャネルで何倍も違うので、幅で置き、必ず `推定` と書く。最初の施策で実データを取る。

| 段階 | 仮置きの幅 |
|---|---|
| LP 訪問 → 申込完了（セルフ申込・低単価） | 1〜5% |
| 申込開始 → 申込完了（フォーム） | 40〜80% |
| 訪問 → 無料トライアル登録 | 2〜10% |
| トライアル → 有料（カード登録不要型） | 5〜20% |
| トライアル → 有料（カード登録必須型） | 30〜60% |
| B2B 問い合わせ → 商談化 | 20〜50% |
| B2B 商談 → 受注 | 15〜35% |
| B2C サブスクの月次解約率 | 3〜10% |
| B2B SaaS（中小向け）の月次解約率 | 1〜4% |

## 5. CSV の形式（`keiyaku.py funnel` の入力）

上から段階の順に並べる。1行目は見出し。`target` は目標の転換率（前段階比、0〜1）で、空欄なら計算しない。`note` に `推定` などを書く。

```csv
stage,count,target,note
LP訪問,20000,,GA 直近3か月の月平均
料金ページ,6000,0.35,
申込開始,900,0.2,
申込完了,450,0.7,
初回利用,300,0.8,推定
```

出力の見方:

- `rate`：前段階からの転換率。`drop`：前段階から落ちた数。
- `gain@target`：その段階だけが `target` に届いたとき、最終段階が何件増えるか。**この値が大きい段階が詰まりの候補**。
- `gain@+10%`：その段階を相対 10% 改善したときの増分（どの段階でも同じになることの確認用）。
