# 仮説・優先順位・検証

## 1. 仮説の書き方

```
もし △△（施策: どの画面・文言・手順・枠をどう変えるか）なら、□□（指標と分母）が X% → Y% に上がる。
根拠は 〇〇（顧客の声の引用・観察・数字）。期限時点の有効契約数 +Z（`funnel --set 段名=Y` か `stock --churn-x` の出力）。
```

- X は実データ。Y の根拠が無ければ控えめ（相対 +10〜20%）に置き「見込みの根拠なし」と書く。1仮説1指標。

## 2. 優先順位

`効果 × 確からしさ ÷ 手間`（各1〜5）で並べ、上位3件を段5へ渡す。

| 軸 | 5 | 3 | 1 |
|---|---|---|---|
| 効果（期限時点の増分 ÷ 目標までの差。目標の単位に揃える: 売上なら増分×ARPU。差が無ければ悲観ケースとの差） | 30% 以上 | 10〜30% | 10% 未満 |
| 確からしさ | 顧客の言葉と数字の両方 | どちらか一方 | 推測のみ |
| 手間（重いほど大きい。割り算の分母） | 1か月以上・外注・開発大 | 1〜2週間 | 1人日未満・費用ほぼなし |

- 流入を増やす施策（広告費増・チラシ増など）は、`levers.md` 1 の条件（各段の率が目安以上で母数だけが足りない）を満たすときだけ上位に置ける。満たさないなら点数にかかわらず、受け皿の段を先に直す施策の後に回し、理由を書く。
- 計測の仕組みが無い段の「計測を入れる」は、効果が低く見えても1番目に置いてよい。
- 戻せない施策（値上げ・プラン廃止）は確からしさ4以上を求める。

## 3. A/B テストの設計（結果を見る前に固定する）

1. 指標1つと分母。振り分けはユーザー単位でランダム。
2. `ab-size --base <今の率> --mde <相対差> --daily <1日の流入>`。有意水準5%（両側）、検出力80%。
3. 8週を超えるとスクリプトが「A/Bテスト不適」を出す。そのときは5へ。最低1週間、できれば2週間単位。
4. 合格線（例「事前の標本数に届いて ab-judge が有意に高い」）と中止条件（不具合、解約率・返金・問い合わせの悪化）。

禁止: 途中で何度も見て有意になった時点で止める／期間中に価格・広告費を変える／指標を後から選び直す／申込だけ見て継続を見ない。

## 4. 判定

- `ab-judge --a N X --b N X --planned <事前の1群の標本数>`。期待度数5未満は Fisher、それ以外は z 検定、区間は Newcombe。
- 事前の標本数に未達は「途中経過・判定不可」。SRM 警告（p<0.001）が出たら振り分けを直すまで使わない。
- 無作為でない群（導入支援の有無、チャネル別など）は `--observational`。SRM を省き「因果は未確認」と出る。
- 有意でも、区間の下限が事業上意味のある大きさか確かめる。有意差なしは「差が無い」ではない。

## 5. テストできないとき（小母数・B2B・店舗）

- **上流の指標で測る**: クリック・申込開始・体験申込など母数の多い段。後で契約との関係を確かめる。
- **差の大きい変更に絞る**: 相対 +30% 以上を狙える変更だけ試す。
- **before-after**: `before-after --before ... --after ... --ly-before ... --ly-after ...`。同じ長さの期間で比べ、前年同期を季節の基準線に並べる。結論の既定は「判断できない」。前年同期と比べても差が残り p<0.05 のときだけ「差あり（因果は未確認）」。同じ期間の広告費・価格・チラシ・人員・新店の変化を並べて書く。開業1年未満は基準線が無く、ほぼ常に「判断できない」。
- **拠点・担当・期間で分ける**: 条件の近い2群で比べる。見込み客5人に見せて迷った点を聞く（原因の確かめに使う）。
